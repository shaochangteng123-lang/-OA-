# 社保回单识别回归修复与生产发布

## 原因

2026-09-08 已上线的社保遮挡收款账号修复使用识别版本 6。2026-09-14 的合同下载功能发布后，当前生产镜像中的工资路由退回识别版本 3，人力成本识别服务也丢失社保遮挡账号兼容和电子回单号事务查重接线，因此工行“待报解预算收入”回单再次提示无法识别收款账号。

生产数据库中的两条失败记录均由版本 3 处理，金额为 0，未建立电子回单号登记。回单原图上的收款账号由银行遮挡，不属于虚假回单。

## 修复

- 恢复社保识别版本 6、国库缴款遮挡账号严格校验、补打回单错行金额处理及电子回单号事务查重。
- 恢复旧版本记录的升级识别接线；同一回单号跨文件和跨月份仍只能登记一次。
- 新增发布回归测试，固定校验版本、遮挡账号入口、事务查重和数据库唯一约束。
- 生产容器启动时再次检查社保识别版本不低于 6、遮挡账号兼容和电子回单号查重服务。任一接线被旧发布覆盖时，容器拒绝进入健康运行状态。
- 候选镜像基于当前 2026-09-14 最新生产镜像，仅覆盖工资路由、人力成本识别、付款回单解析、电子回单号查重服务和启动脚本，保留合同下载及其他已上线功能。

## 验证

- 用户本次提供的两张工行补打回单在无网络、无数据库连接的候选镜像中识别成功：19,834.44 元对应电子回单号 0920-5144-9671-1100；40.17 元对应电子回单号 0920-2021-0505-1100。
- 完整发布检查通过 256 套、3,504 项测试；相关 47 项测试、类型检查、代码检查及编译文件语法检查通过。
- 旧生产镜像与新启动脚本组合时会因社保识别版本 3 被明确拒绝，候选镜像通过启动门禁。
- 生产数据库及切换前业务摘要已经备份。没有替用户上传回单，也没有修改现有两条失败记录。
- 完整统一镜像在正式生产通过启动门禁，健康检查和首页均返回 200；业务表及人力成本表切换前后指纹一致。
- 两张用户补打回单在正式生产镜像中只读识别为 19,834.44 元／0920-5144-9671-1100 和 40.17 元／0920-2021-0505-1100，验证过程未写入数据库。
