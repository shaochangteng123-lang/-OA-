# 合同台账开发转生产迁移说明

## 目的

将开发环境中已经完成历史导入、调试增减和人工确认的最终合同台账，定向迁移到生产环境。迁移只处理合同业务子图及其原始附件，不覆盖生产环境其他业务数据。

本次冻结批次为 `contract-ledger-finalized-2026-08-28-v1`，正式迁移包清单摘要为：

```text
ea33c7e74e0ce71099fe8cf56a8adbd21add754343521122cced1c063ef566b3
```

## 已确认迁移范围

- 合同及关联协议104条，其中主合同75条、补充协议27条、解除协议2条；
- 当前有效记录102条、软删除历史记录2条；
- 合同发票、主营回款、合同付款、最终对外付款、财务登记、登记明细和金额对应关系；
- 开发历史导入后新增并已确认保留的10条付款识别记录；
- 1笔押金、1份押金凭证和2条付款用途拆分；
- 合同审计记录及辅助档案；
- 36张合同白名单表，共1996行，其中18张表存在数据；
- 406个附件保存路径、404份唯一附件内容，逐一执行字节数和 `SHA-256（安全散列算法）` 校验。

## 明确不迁移的数据

- 开发账号：只按用户名、姓名和角色唯一映射为生产管理员账号；
- 开发项目：当前合同没有项目外键，不复制项目表；
- 合同费率配置：生产保留自身4条配置，只比较业务值指纹；
- 月度财务报表、银行文件、银行交易和10条开发月报关联；
- 报销、人事、工资、工作日志及其他非合同数据。

合同自身的回款、付款和凭证会完整迁移。生产月报中的银行回单关联必须在生产环境重新上传或同步银行回单后重建，不能引用开发月报主键。

## 工具

- `server/scripts/export-contract-ledger-snapshot.ts`：只读导出开发最终台账；
- `server/scripts/import-contract-ledger-snapshot.ts`：生产预演和提交；
- `server/scripts/contract-ledger-snapshot-format.ts`：固定白名单、清单格式和语义结构校验。

生产镜像不包含 `tsx（TypeScript直接执行器）`，生产环境必须执行编译后的：

```text
node dist/server/scripts/import-contract-ledger-snapshot.js
```

## 安全机制

1. 导出器只允许在 `NODE_ENV=development（开发运行环境）` 执行，且输出目录必须不存在；
2. 迁移包内每张表和每份附件都有独立摘要，清单自身还有内容摘要和最终摘要；
3. 生产预演要求列结构精确兼容，生产约束和索引不得弱于开发来源；
4. `dry-run（预演）` 会在数据库保存点内真实插入完整合同子图，再完整回滚，不写附件、不改变序列；
5. 生产账号必须唯一匹配且处于启用状态；
6. 生产合同域必须为空，或已经与同一迁移包逐行完全一致；部分导入、内容变化或其他合同数据都会阻断；
7. 生产报销发票号码、附件摘要和付款回单号存在冲突时阻断；
8. 附件同路径同摘要可复用，同路径不同摘要立即阻断；
9. 提交使用单一数据库事务；失败时回滚数据库并清理本批新建附件；
10. 合同编号序列只允许向前推进，绝不覆盖为更小值；序列推进位于全部数据校验之后。由于 PostgreSQL（关系数据库）的序列不随事务回滚，极端提交失败最多留下安全号段空洞，不会倒退或产生重复编号；
11. 相同迁移包重复提交时严格幂等，不重复写入。

## 正式执行顺序

### 1. 冻结和核对迁移包

正式包当前位于：

```text
debug/contract-ledger-final-snapshot-2026-08-28
```

不得修改包内任何 `JSON（结构化数据）` 文件或附件。任何修改都会导致摘要校验失败。

### 2. 先在生产副本演练

必须使用最新生产数据库备份恢复一个隔离数据库，并使用独立附件目录依次完成：

1. 空目标预演；
2. 首次提交；
3. 同包再次提交，验证幂等跳过；
4. 人为制造附件冲突，验证失败关闭；
5. 人为增加目标检查约束使中途插入失败，验证数据库与附件均无残留；
6. 核对生产副本原有账号、报销、月报和费率配置完全不变。

### 3. 正式生产前备份

执行最新生产数据库和 `uploads/production` 完整备份并验证可恢复。备份未完成或校验失败时不得继续。

### 4. 放置受控迁移包

迁移包可放在生产上传挂载目录的专用临时目录，但不能放宽整个上传目录权限。例如：

```text
/app/uploads/.contract-ledger-migration/ea33c7e74e0c
```

若文件由 `root（超级用户）` 复制，必须只对该精确目录调整为生产进程账号可读，禁止对整个 `/app/uploads` 递归放宽权限。

### 5. 阻断用户入口并预演

先停止生产反向代理，阻断新增请求；保持生产应用容器运行，以便执行已编译导入器。然后运行：

```bash
NODE_ENV=production node dist/server/scripts/import-contract-ledger-snapshot.js \
  --dry-run \
  --bundle /app/uploads/.contract-ledger-migration/ea33c7e74e0c \
  --storage-root /app
```

只有预演输出 `blockers（阻断项）` 为空、账号映射为1、数据库状态为空、记录数1996且附件路径数406时，才可继续。

### 6. 正式提交

```bash
NODE_ENV=production node dist/server/scripts/import-contract-ledger-snapshot.js \
  --commit \
  --bundle /app/uploads/.contract-ledger-migration/ea33c7e74e0c \
  --storage-root /app \
  --confirm-production=IMPORT_CONTRACT_LEDGER_TO_PRODUCTION \
  --manifest-sha256=ea33c7e74e0ce71099fe8cf56a8adbd21add754343521122cced1c063ef566b3
```

命令结束前不得关闭终端、重启容器或重新执行。如果出现“数据库提交结果无法确认”，必须保留现场并先核对数据库和附件，禁止直接重试。

### 7. 提交后验收

- 合同及协议104条，合同台账当前显示102条；
- 财务登记59条、登记明细199条、金额对应关系110条；
- 406个附件路径全部可读取并通过摘要校验；
- 合同列表、合同详情、财务闭环、发票／回单在线预览、押金管理和审计记录正常；
- 生产账号、报销、月报、工资、项目及4条费率配置均未变化；
- 合同编号序列下一值不小于106；
- 月报关联保持生产原状，后续由生产银行回单重新同步。

验收完成后恢复反向代理，再用相同迁移包执行一次预演，结果应显示已经完整导入且可幂等跳过。

## 回滚

正式提交前的数据库与上传附件备份是唯一完整回滚基线。需要回滚时：

1. 再次停止生产入口；
2. 恢复提交前生产数据库备份；
3. 恢复提交前 `uploads/production` 完整备份；
4. 核对合同域恢复为空，其他业务数据与回滚基线一致；
5. 验证服务健康后恢复入口。

不要只删除合同主表，也不要手工删除部分附件，否则会破坏财务登记、审计和附件对应关系。
