# 11-人事管理模块

## 模块概述

人事管理模块负责员工全生命周期管理，包括入职、转正、离职、请假、人力成本等人事流程的申请、审批和数据管理。

## 主要功能

### 1. 入职管理

- 员工填写、保存草稿并提交个人入职档案
- 管理员维护入职模板、查看和编辑员工档案
- 工作信息中的入职日期不可手工编辑，劳动合同识别成功后取最早合同开始日期自动显示
- 实习期员工在合同识别出入职日期和试用期截止后自动建立待提交转正记录

### 2. 转正管理

#### 用户端功能（转正申请页面）

- 查看实习期状态（入职日期、试用期截止、剩余天数；两项日期均来源于劳动合同识别）
- 点击“申请转正”进入独立填写页面，直接在管理员上传的转正申请单原始模板上选择转正类型、填写本人述职，无需下载或重新上传整张申请表
- 系统自动带入申请人、所属部门、岗位职务、入职日期和转正定岗；这些字段不能由员工手工改写
- 员工先在个人设置中保存签名，点击原模板中的本人签名栏调用并回填后提交；服务端签署日期自动作为申请日期
- 申请提交后，员工可在转正状态页点击“查看申请表”，以只读方式查看本次提交时的员工信息快照、本人述职和已完成签名
- 驳回后保留旧版本签署记录，员工修改述职并重新签名后生成新版本
- 查看主管领导意见、人事部意见和总经理审批的处理进度；管理员上传正式盖章文件后在线预览正式转正申请单
- 管理员将员工重新调整为实习期时，上一轮转正流程及审批快照归入历史转正记录；员工再次提交申请后仍可在状态页查看上一轮审批明细

#### 管理端功能（转正管理页面）

- 上传/管理转正申请表底稿；员工和各级审批人直接在该原始模板上填写，底稿不提供员工下载
- 管理员和超级管理员只从“员工数据 > 转正管理”处理转正，不再显示人力资源区审批中心入口，个人“转正”页也不承载审批功能
- 转正管理分为“待我签署”“本月已审批”“全部查询”，可查看待转正员工、当前状态、申请详情、正式文件及完整审批流程
- 主管领导意见固定由活动总经理账号填写并签名；人事部意见由指定管理员签署；最终审批由指定董事长使用本人签名完成
- 总经理、管理员和董事长都只在个人设置保存本人的一份签名，进入本人负责的环节后点击“签名”调用
- 每一环节都按本次申请保存的具体审批账号、当前阶段和登录账号校验，不允许其他同角色账号代签
- 董事长完成最终审批签名后，系统自动生成“转正结论”中的职工、拟定岗位、执行岗位及结论日期，并生成可下载打印的待盖章 PDF（便携式文档格式）底稿
- 管理员打印盖章后在员工数据“转正档案”上传正式文件；该文件同步成为员工端、员工转正档案和转正申请列表中的唯一正式转正申请单
- 全部审批完成但正式盖章档案尚未上传时，员工数据菜单、转正管理页签和页面提醒区同步显示待归档数量；直接创建为在职且没有转正流程的真实员工，未补录正式档案时同样提醒；上传成功后立即清除对应提醒。超级管理员、老板和董事长等系统专用账号不参与员工提醒统计
- 转正统计数据展示
- 管理员可在员工数据页收到实习期到期前 30 天或已到期提醒，并跟进转正材料
- 员工、主管领导意见、人事部意见和最终审批的签名日期分别由服务端签署时间生成，不能由前端手工指定
- 在线申请单和生成底稿中的年、月、日数字按本人、主管领导、人事部、总经理及结论各栏的原始文字坐标分别校准，与模板原有“年”“月”“日”保持同一基线
- 转正在线内容只允许在员工待填写或驳回状态修改；主管签名后员工不能撤回，终审后流程数据锁定，管理员再归档正式盖章文件
- 实习期员工不能通过员工编辑或用户管理直接改为在职，必须先完成转正审批

#### 电子签名说明

- 员工、总经理、管理员和董事长都需提前在个人设置保存本人的一份签名。签名图片可使用纯白纸签名照片、扫描件或透明底图片，无需打印或手工填写整张转正申请单
- 进入负责的转正签署环节时签名栏保持空白，点击“签名”后才调用本人签名；未保存签名时提示先前往个人设置，申请单内不提供临时上传窗口
- 个人设置上传签名时，系统按每个像素周围的局部背景识别真实细笔画，并通过连通区域筛选去除底色、强阴影、边缘暗块和孤立纸张颗粒，裁剪多余留白；点击申请单签名按钮后按笔迹比例回填，本人确认提交时服务器再次处理图片并形成签署记录
- 系统保存签名图像、签名类型、签名人姓名、实际操作账号、操作人姓名、角色、部门、职位、意见、决定、签署时间和申请版本，用于内部流程留痕
- 页面中的电子签署记录只展示实际操作人，不再单列签名归属人；每个节点显示该版申请实际保存并完成签署的审批人姓名
- 转正提交会复制当时使用的签名作为该申请版本快照；个人设置后续更换或删除签名不会修改历史转正档案
- 当前实现属于企业内部图片电子签名流程，不等同于 CA（证书颁发机构）签发的数字证书；若将来需要对外合同级法律效力，应接入合规电子签约服务完成实名认证、证书签发、时间戳和防篡改存证

### 3. 离职管理

#### 管理员端功能（员工数据 > 离职管理）

- 离职不再提供员工端申请页面，也不进入审批中心；管理员和超级管理员统一在员工数据中办理
- 维护五类 PDF（便携式文档格式）模板：终止 / 解除劳动关系协议书、员工离职交接单、薪资及各类款项结算确认书、离职经济补偿协议书、离职证明
- 为在职或实习期员工创建离职人员记录；历史已离职但尚无离职记录的员工可补建档案；同一员工档案只允许创建一条记录
- 新上传仅支持真实 PDF（便携式文档格式），并以管理员上传的原页面为底稿在线填写；历史 DOCX（开放 XML 文字处理文档）模板保留兼容读取
- 五类模板保留每页原“编号：”，将完整编号统一生成为 `YULI-CS员工数字-LZ1` 至 `YULI-CS员工数字-LZ5`，整段保持一致的红色、文字高度和基线
- 自动填充姓名、身份证号、部门、职位、首次劳动合同年月、离职日期、入职日期和任职年限；交接单正文及三个附件中的员工姓名分别填写
- 自动字段仍可由管理员在线修改，并可增加、移动自定义文字；五类模板可分别下载或合并为一份后统一打印
- 单独上传五类 PDF（便携式文档格式）档案，或上传合并 PDF（便携式文档格式）后一键识别、拆分并自动入位
- 五类当前档案齐全后，离职记录由“档案待完善”自动进入“待确认离职”；此时员工仍保持原在职状态，原账号仍保持激活
- 管理员逐项预览并点击“确认离职并停用账号”后，系统才在同一事务中将员工状态改为已离职、完成离职记录并停用原账号
- 已完成档案允许替换错传文件，但不能删除到不完整；替换档案不会再次停用后来由管理员人工激活的旧账号
- 已离职员工的原档案不能恢复为在职；返聘必须新建账号和新员工档案

### 4. 请假管理

- 新建请假申请
- 请假申请编号统一显示为 `QJ-YYYY-NNNNN`；历史 `LR` 编号在服务启动时同步转换
- 总经理在人力资源区“审批中心 > 请假审批”处理普通员工申请；董事长在“员工数据 > 请假管理 > 请假审批”处理总经理申请，并分别查看本人审批记录
- 请假流程中的审批身份按账号角色展示，总经理刘行显示为“总经理 刘行”，不使用其员工档案中的“项目经理”职位覆盖
- 请假待审批列表的提交时间和审批记录的审批时间均按完整北京时间在同一行展示
- 管理员和超级管理员在“员工数据 > 请假管理 > 抄送记录”查看全员申请、附件和审批进度，不显示通过、驳回、审批记录或审批待办角标
- 个人“请假”页面只展示本人余额、申请表单和申请记录，不再混入审批任务
- 请假审批通过后，员工在系统任意业务页面收到成功通知，请假菜单显示未读数量；进入请假页可查看成功横幅，关闭后标记为已读并清除角标。驳回提醒按申请计数，员工成功打开对应申请详情后立即标记为已读并同步消除顶部提示和菜单角标
- 管理员请假记录展示全员申请、附件、审批进度、距返岗的剩余自然天数和返岗日期、上午或下午时段；返岗日期排除周末、法定节假日并识别调班工作日
- 管理员“员工余额”按所选年份显示完整年份，带出员工编号，并按员工编号排序后为全部活动账号补齐适用的假期余额；每个人的年假至少显示配置的基础额度，有有效入职日期时再按工龄上调，产假和陪产假继续按性别过滤
- 新建请假与驳回重提共用带节假日标记的日期选择器；法定节日显示节日名称和“休”，调休工作日只在右上角显示“班”并支持悬停查看具体补班名称，普通周末只在右上角显示“休”
- 请假类型管理（年假、带薪事假、病假、调休假、婚假、产假、陪产假）
- 请假记录查询
- 同一员工不能提交与待审批或已通过记录重叠的日期和半天时段；并发提交会按员工串行检查
- 审批资格按数据库实时角色校验；普通员工申请只有指定总经理可以审批，总经理申请只有指定董事长可以审批，管理员和超级管理员仅作为抄送对象，任何角色都不能审批本人申请
- 申请提交时保存具体审批人：普通员工选择活动总经理，总经理选择活动董事长；对应角色没有可用账号时拒绝提交并提示管理员配置

### 5. 员工数据管理

- 员工信息查看和编辑
- 员工统计数据展示
- 员工数据导出
- 员工详情新增“转正档案”，正式区域只查看管理员上传的盖章转正申请单；系统终审生成件作为打印底稿，不冒充正式档案
- 正常流程中的待填写和已驳回记录由员工本人在线填写述职并重新签名，管理员不能替员工上传或代提交申请表
- 正常转正流程终审后生成待盖章 PDF（便携式文档格式）底稿；管理员上传盖章文件后才进入员工详情正式档案，待填写、签署中和已驳回状态不展示过程文件
- 直接在职员工的补录材料明确标记“管理员补录”，不生成或伪装成已通过的转正审批记录
- 员工状态管理（在职、试用期、休假中、已离职）
- 已批准请假进入生效日期和上午、下午时段后，员工列表、状态筛选和统计自动显示“休假中”；返岗时段到达后恢复展示原始的在职或实习期状态，不改写员工基础状态
- 管理员编辑员工时可在人事档案中一次选择多个 PDF（便携式文档格式）；单个文件可包含多类材料，系统逐页识别标题、按连续页段拆分后分别归档
- 自动识别覆盖入职邀请函、新员工入职申请表、劳动合同书、保密协议、个人声明、2025年度公司电脑管理办法、身份证复印件、入职体检报告、学历证书复印件和工资卡复印件，并增加“其他”收纳类型
- 文档类型顺序不固定，系统以每类首页为边界，不依赖固定页码；未出现的类型保持缺失，不生成空记录
- 同一批次中再次出现同类型首页且中间已有其他档案时，系统保留为另一份连续页段，不把不相邻页面跨材料合并
- 固定十类材料按页面最靠前的正式主标题优先分类，正文或附件中出现其他档案名称不会抢占主类型；扫描标题漏识别时会提高分辨率复核，并通过各自正文组合特征确认
- 保密协议与其后独立的个人声明按各自首页分别切分；个人声明兼容“本人谨此声明”“特此声明”“姓名”等扫描正文特征，不再静默并入保密协议
- 扫描页先使用 300 DPI（每英寸点数）标题区快速筛查；未发现边界时再放大识别页面中央主标题，且只允许固定档案精确标题触发切段，正文组合、印章噪声和通用“其他资料”文字不会被聚焦结果单独采用；完成聚焦复核后，文字充分且置信度达标的明确续页不再重复整页识别，证据不足、候选冲突、合同、保密协议、个人声明及证件类页面继续执行 480 DPI（每英寸点数）标题增强或 300 DPI（每英寸点数）整页兜底
- 页面元数据正常但扫描图像横置时，系统根据 OCR（文字识别）文字框方向触发局部旋转复核；正常页和没有纵向证据的少字续页不增加识别次数，横置异常页复用一次整页渲染并检查 90°、270°，倒置文字由识别引擎已有的行方向校正处理；旋转后的精确首页标题可建立新页段，学历、身份证和银行卡等结构唯一的证件还允许两方向一致的组合证据，合同、申请表、保密协议等正文弱组合仍不能单独触发切段
- 自动拆分在写入前校验 1 至总页数必须各出现一次；任何源页遗漏、重复或越界都会停止整批落库，防止提速或方向修正造成静默丢页
- 低风险类型只有两种文字排序都得到前置精确标题、完整正文结构且无竞争类型时才省略增强轮；不同固定类型冲突、固定类型与明确“其他资料”冲突、页面复核后仍缺少有效文字，或多页文件没有可靠页段边界时，整份文件拒绝落库并提示具体页码或原因
- 分类阶段已经得到的图片候选会按页复用于邀请函工资和劳动合同期限解析；准确文字层始终优先，多个候选解析结果不一致时自动执行原有高分辨率回退，不以提速替代字段准确性
- 横向学历证书即使标题被文字识别拆散，也会通过普通高等学校、证书编号和准予毕业等组合特征判断；识别出多类材料的合并文件仍有缺失类型时会提示管理员核对
- 工商银行卡实物复印件不依赖完整识别“借记卡”或卡号；系统以工商银行品牌片段和持卡人签名、本卡不得出租转借、拾获归还说明、有效期等卡面专属文字共同确认边界，仅出现开户行和工资卡账号的表单不会归入银行卡
- 不属于固定十类的明确离职证明、职业资格材料等页段不会并入相邻档案；通用“其他资料”标题只有整页与标题区两路识别一致时才自动归档，“成如下协议”“达成如下协议”等正文断句不会被当成标题，单次弱结果或与固定类型冲突时会停止上传并提示核对
- 内容可读但无法明确分类的单页 PDF（便携式文档格式）会归入“其他”；多页文件没有可靠边界或页面缺少有效识别文字时不会静默并入相邻档案，管理员可拆分后在对应档案行或“其他”行手动上传
- 一键识别上传由全局共享队列按文件串行处理，单个文件最长等待 40 分钟；关闭员工窗口或切换系统内其他业务页面不会建立第二条并发队列，页面上方正中持续显示当前员工、文件、等待数量和“等待识别 / 正在识别”状态。识别中使用蓝色、完成使用绿色、需核对使用黄色、失败使用红色，并通过彩色边框和阴影保持醒目；浏览器刷新、关闭标签页或退出登录会结束当前页面的状态展示，不能据此判断服务端结果
- 文件校验、识别失败、分类冲突、缺失类型及后续字段识别失败提示均保留在对应员工的人事档案页内，最新问题优先显示，每个文件拥有独立提示，只有管理员点击对应关闭按钮后才消除；代理返回网页异常、网关超时或连接中断时统一提示识别结果暂时无法确认、不要重复上传并先刷新档案核对，不再直接显示含义不明的“服务器返回异常（500）”或“上传失败”
- 一键识别接口明确返回且固定十类全部归档、没有额外材料或后续识别问题时，对应员工的人事档案页会显示绿色“人事档案已全部识别并上传成功”提示，并列出该文件实际归档的档案类型；存在缺失类型、额外材料或后续识别失败时，系统固定顶部栏改为黄色“需核对”，不得显示绿色完成。最终提示均可手动关闭，即使管理员已退出员工窗口或切换到其他业务页面也能看到结果，多文件上传时每个文件分别保留并可依次关闭
- “其他”不属于必备档案，不影响固定十类的档案完成度和 10/10 计数
- 劳动合同书每次上传均新增归档，不覆盖旧文件；合同结束日期最晚的一份标记为当前合同，其余标记为历史合同
- 员工端“入职 > 入职文件”的劳动合同原文件按当前合同优先展示，每份文件后显示“当前合同”或“历史合同”标签及合同起止日期
- 合同扫描件自动识别起止日期和试用期截止日期；系统以第一份劳动合同作为入职日期和试用期截止依据，续签不覆盖
- 员工入职日期取第一份已识别合同的开始日期，续签不会改变入职日期；员工和管理员均不能手工修改
- 没有上传劳动合同或合同起止日期识别失败时，员工端和员工数据列表的入职日期均显示为空
- 删除合同时重新确认剩余档案中的第一份合同和当前合同；没有可识别合同后，入职日期和合同到期时间显示为空
- 人事档案完成度行最右侧提供“一键删除”，与“一键识别上传”并列；无档案时不可点击，执行前必须二次确认
- 一键删除会清空该员工全部人事档案并同步清空入职日期和合同到期时间，但保留邀请函工资基线、已生成的历史工资记录和管理员手工工资金额
- 入职邀请函公共模板每一页都必须保留右上角“编号”；劳动合同书第 1 页保留右上角黑色编号，第 2 页起每一页保留左上角蓝色“合同编号”；新员工入职申请表第 1 页保留“员工编号”
- 2025年度公司电脑管理办法需每一页保留“编号”，并保留“附件1 笔记本电脑协议书”中的甲方、乙方和身份证号码位置；员工预览或下载时自动在每一页带入员工编号，并写入甲方单位“北京羽隶工程咨询有限公司”、乙方姓名和身份证号码
- 员工下载上述模板时，系统在全部目标页自动带入用户管理中的最新员工编号；管理员预览的是未写入个人编号的原模板
- 管理员可在“员工数据 > 编辑 > 工作信息”选择合同模板期限和可选试用期；日期范围必须完整、顺序正确，试用期不得超出合同期限
- 管理员在用户管理或员工数据中均通过“部门—职位”联动下拉选择职位；员工数据不再允许手工输入，保存后账号与员工档案同步
- 员工端显示管理员拟定的合同模板日期，劳动合同书预览和下载时自动把年月日写入第二页对应空位；未设置当前合同模板期限时下载保持锁定，预览中的合同期限和试用期全部保持最新版模板原有空白，第四条岗位仍使用员工当前职位
- 劳动合同下载锁定时，员工将鼠标悬停在下载按钮上会提示“下载已锁定，请等待管理员设置合同期限后下载”；入职文件页每 3 秒静默刷新一次合同模板状态，并在切换页签、窗口重新获得焦点时立即刷新
- 正式劳动合同上传至人事档案后，系统清空当前模板日期；员工端下载立即锁定，预览回到最新版模板的空白日期并保留当前职位，管理员设置下一期合同模板起止日期后才写入新日期并重新开放下载
- 劳动合同在线预览通过新标签页进入独立页面逐页渲染，不使用浏览器原生文件查看器，不显示下载或打印入口，并在预览期间阻止保存和打印快捷键；预览画布按页面实际显示宽度、设备像素密度和额外高清采样生成，固定正文保持源 PDF（便携式文档格式）的矢量清晰度，不再把低分辨率画布放大显示
- 合同模板中的员工编号和自动日期按每次上传源 PDF（便携式文档格式）中相邻文字动态继承字体类别、字号和颜色，不绑定开发或生产环境的固定模板；劳动合同第一页自动识别源文件中的编号下划线，编号在完整线段内水平居中并向上留出小间距；只有源字体名称明确标注粗体时才使用粗体，普通 `SimHei（黑体）`不再触发额外加粗
- 劳动合同第二页第四条自动把员工当前职位写入“担任……岗位（工种）工作”位置；职位来自管理员选择，不依赖合同文字识别或员工手工填写，并按当前上传源合同的字段坐标、字体类别、字号和颜色生成；覆盖时清除原示例文字边缘，下划线与相邻汉字基线对齐
- 合同模板日期仅用于生成待签文件，不替代正式归档依据；签字合同上传后，入职日期、合同到期及试用期仍以合同识别结果为准
- 用户管理修改员工编号后不需要重新上传模板；员工下次下载上述模板时自动使用最新编号
- 管理员补录或上传的人事档案按上传时的样子保存、展示、预览和下载，不覆盖文件内原编号，也不因用户管理改号而修改历史档案文件名
- 管理员“员工数据 > 基本信息”和员工端“员工基础信息 > 工作信息”统一显示只读的“入职日期”和“劳动合同”；入职日期来自最早合同开始日期，劳动合同展示当前合同起止日期
- 入职日期使用完整的只读方框展示；无合同时显示“暂无入职日期”，完整来源说明放在悬停提示中，避免窄列截断
- 当前合同进入到期前 10 天后，员工基础信息顶部置顶显示到期提示，左侧“入职”菜单显示红色角标；到期前显示剩余天数，到期当天显示“今天到期”，到期后显示已逾期天数，上传续签合同后自动切换到最新合同日期

### 6. 人力成本

- 入口位于“员工数据”页签内，并排列在“请假管理”之后
- 页面及接口仅管理员、超级管理员可访问，员工端不提供个人工资查看入口
- 超级管理员对应系统维护账号，仅拥有管理权限，不作为员工进入工资表或人力成本合计
- 按月展示与公司工资表一致的多级表头，完整区分单位承担、个人承担、代扣和实发工资明细
- 人力成本拆分展示本月工资、单位社保、个人社保、单位公积金和个人公积金；单位与个人缴纳部分不得混合为一个无法解释的总数
- 公司人力成本合计等于本月工资总额加单位社保总额、单位公积金总额。个人社保、个人公积金和个税属于从员工工资中代扣的个人缴纳，不属于公司额外承担，不得在公司人力成本总额中重复计入
- 工资表实现上仍可用代扣合计加实发工资得到同一公司成本结果，因为个人缴纳和个税已从本月工资中抵减；看板和工资表均使用精确十进制口径
- 羽隶经营看板只读展示上述公司级汇总、单位／个人缴纳拆分和个税代扣，不返回员工个人工资明细；个税代扣按工资月份直接汇总 `payroll_records.individual_income_tax`，仅用于展示和实发工资核对，不重复计入公司人力成本
- 看板按月时只汇总所选单一自然月的工资记录，按年时汇总所选自然年 1 月至 12 月的工资记录；顶部人力成本指标、薪资汇总和财务趋势共用同一 `startMonth`／`endMonth`
- 单月人均人力成本以该月工资记录人数为分母；多月及年度展示人月均成本，以所选周期全部工资记录人次（人月）为分母，避免使用当前在职人数错误折算历史成本
- 看板“人员与日志”分区展示当前员工档案和当前日志状态，不受财务月份或年份筛选影响，不得将当前人员结构伪装为所选历史周期快照
- 羽隶经营看板首次加载后每 30 秒静默自动同步。访问角色显示为 BOSS，内部角色编码仍为 `boss`
- 管理员可分别修改所选月份的本月工资、公积金缴费基数、社保缴费基数和应纳个税
- 单位与个人社保均按社保缴费基数计算：养老分别为 16% 和 8%，医疗分别为 9.8% 和 2%+3 元，失业均为 0.5%，单位工伤为 0.4%
- 单位与个人住房公积金均按公积金缴费基数 × 6% 计算；实发工资为本月工资减个人社保、个人住房公积金和应纳个税。每名员工的社保各险种、公积金和个税均先四舍五入到分，再计算员工合计与全员合计，保证合计等于页面已显示分项并与税务缴费口径一致
- 所选工资月份下可分别上传社保、公积金、个税和实发工资银行回单；回单按工资归属月份独立保存，通常在次月上传上月资料，切换月份只展示对应月份文件
- 每个月份、每个类别仅允许保留一个上传批次：首次可一次选择多个银行回单；只要该类别已有文件，银行回单上传区即锁定，删除该类别全部文件后自动解锁。个人个税明细入口独立，不受个税银行回单锁定影响
- 四类回单均支持点击或拖拽上传 PDF（便携式文档格式）、JPEG（图像格式）和 PNG（便携式网络图形），单次最多 20 个文件，单个文件不超过 50MB
- 上传文件名由前端按 UTF-8（统一字符编码）显式提交，后端同时兼容修复历史单字节乱码，列表和预览均显示原中文名称
- 四类回单与财务区审批中心使用相同的银行回单真实性校验；PDF（便携式文档格式）支持多文件、多页和同页上下两笔工行回单的自动拆分识别
- 公积金、社保和个税回单支持机构类收款人；OCR（文字识别）漏掉第二个“户名”标签时，系统可从“住房公积金管理中心”等机构全称兜底确认收款人，不再按个人姓名长度误判
- 实发工资只汇总摘要、用途、备注或客户附言中明确为工资的回单；其中银行回单“备注”字段只要包含“薪资”，即明确作为工资用途候选，再继续执行银行回单真实性校验。同一 PDF（便携式文档格式）中的其他付款回单自动忽略并显示忽略笔数
- 实发工资只要至少识别到一笔有效工资回单就不进入待核查；对应员工的回单合计与账面实发金额不一致时，该员工实发金额标红提示，但仍可点击查看全部对应回单
- 工资回单优先按收款账号、其次按收款户名精确关联员工；明确包含工资或薪资用途且已通过银行、回单、金额及交易凭证真实性校验时，即使文字识别漏掉收款账号，也可按收款户名精确关联员工，不再整笔丢弃。识别结束后自动刷新员工工资表中的回单关联，点击员工“本月实发工资”金额可立即查看对应单笔回单；删除工资回单后同步移除金额入口，同名或无法唯一匹配时提示核对且不错误关联
- 个税卡片内包含“个税银行回单”和“个人个税明细”两个上传入口，两者集中展示、不拆分为独立卡片；前者识别公司个税汇总回单，后者识别工资表中的姓名与“应纳个税”列并自动填充每位员工。应纳个税单元格为空时填 0，未匹配员工保持原值并提示人数；个人个税明细原件按月保存，点击文件名可在线预览；识别结果使用上传框下方的独立状态行，两个上传框始终等高
- 已上传的历史回单会按识别版本在打开对应月份时自动重跑新规则，无需先删除再上传
- 历史回单重识别与新上传识别统一串行执行并按回单编号去重；识别引擎异常时只暂停回单任务，不影响登录、人事档案和其他业务
- 每类回单展示账面金额、识别汇总和差额：社保、公积金分别使用单位与个人缴纳合计，个税使用应纳个税合计，实发工资使用本月实发工资合计
- 同一月份、同一类别下按文件内容摘要防止重复上传；管理员可预览原始回单，并在识别完成后删除错传文件
- 工资表需要管理员主动生成月份，普通读取不会产生或修改工资记录；每次生成都会按日期同步员工范围，入职当月加入，离职当月保留并从下月移除，其他员工跨月保持一致
- 生成新月份时，本月工资、公积金缴费基数和社保缴费基数默认沿用紧邻上月的最终值；应纳个税属于按月确认项目，始终默认 0，待管理员修改或上传当月个人个税明细后填充。已经生成的历史月份继续保持快照，不因后续月份生成或修改而变化
- 管理员修改工资时使用记录版本防止多人覆盖，并保留字段级修改日志
- 金额内部采用精确十进制计算，表格明细和合计统一四舍五入显示两位小数；例如 `7162×9.8%` 显示为 `701.88`
- 入职管理中的入职邀请函为公共模板；工资识别只处理员工详情“人事档案”中的正式入职邀请函
- 正式入职邀请函只读取第一页，优先读取 PDF（便携式文档格式）文字层，失败后使用 OCR（文字识别）；识别成功后直接进入工资计算，无需二次确认
- 自动工资以入职邀请函月度税前工资为初始值，按最早一份已识别劳动合同的开始日期每满 12 个月增加 1000 元；旧员工没有合同识别数据时才回退入职日期
- 自动涨薪最高计算到 10000 元；初始工资超过 10000 元时保留原值；管理员对单月工资的修改不改变后续自动工资基线
- 工资按当月最后一天判断周年：当月任一天满 12 个月，当月整月工资即使用涨薪后的金额，不按天拆分
- 已生成的历史月份保存为快照，不会因当前入职邀请函工资或起始日期变化而在查看时自动改写
- 新上传并成功识别的正式邀请函会立即覆盖当前及未来月份的本月工资，包括此前手工修改的本月工资；缴费基数和应纳个税手工值不受影响

离职模板在线草稿保存 `fieldOverrides`（自动字段及全部空白下划线的修改值）、`fieldAlignments`（各下划线字段的左对齐、居中或右对齐方式）和 `customItems`（历史自定义文字、页码、位置、尺寸、颜色及对齐方式）；原模板文件本身不被改写。管理员从离职人员列表进入独立模板编辑窗口，五类模板不再嵌入员工数据页弹窗。

当前 PDF（便携式文档格式）模板直接作为不可重排底稿；历史 DOCX（开放 XML 文字处理文档）模板先固定转换为 PDF 后继续兼容。图片型或文字结构异常的 PDF 使用 PDF.js（PDF 解析器）补充读取坐标；每页保留原“编号：”，只覆盖该页原完整编号区域并统一重绘，禁止套用其他页面坐标，避免擦除“内部人事文件”等页眉。终止协议首次合同日期按年、月、日完整填充。五套模板的自动字段和管理员在线填写字段分别继承各自所在文字行的真实字体、字号和颜色，不提供手工字号选择；自动字段与下划线保留适当间距。窄空位中的身份证号、完整日期、金额和长职位按实际字形宽度横向适配，并在输入框左右保留安全距离，防止最右侧笔画被裁切。在线预览、单份下载及一并打印使用相同参数。

在线编辑器采用接近文字处理软件的直接操作方式：除姓名、身份证号、日期、部门和岗位等自动字段外，系统还逐页提取 PDF（便携式文档格式）中的全部空白填写下划线及下划线上已有的模板文字，并排除表格边框和普通固定正文。所有填写下划线均为直接编辑区域，点击下划线即可获得输入焦点并填写；下划线已有模板文字且管理员未修改时继续显示原文件内容和样式，只有实际修改后才遮盖原字并写入覆盖层。相邻上下行按各自下划线基线匹配，禁止把上一行误判为下一行字段。选中任一自动字段或下划线后，可在顶部选择文字左对齐、居中或右对齐；离职证明身份证号默认在原留白区域居中。输入内容继承同一行文字的字体、字号和颜色，文字方向保存后同步用于再次打开、单份下载及合并打印。下划线悬停或获得焦点时显示细线提示，但不改变下载文件。历史草稿中已有的自定义文字仍可拖动、调整区域、复制或删除。编辑器提供撤销、重做、页面缩放、适合宽度和快捷保存，并在窗口关闭前保存未提交的填写内容。以上编辑只保存覆盖层，不重排或改写管理员上传的 PDF（便携式文档格式）底稿。

## 入职流程强制引导

员工角色首次登录系统时，会被强制引导到入职页面填写员工基础信息。只有提交员工信息后，才能正常使用系统其他功能。BOSS是独立看板账号，不创建员工档案，也不进入该流程。

### 流程说明

1. **首次登录**: 用户登录后，系统检查其员工信息状态
2. **未填写/草稿状态**: 自动跳转到入职页面 (`/onboarding`)
3. **填写信息**: 用户填写员工基础信息并保存草稿
4. **提交信息**: 用户提交信息后，状态变为 `submitted`
5. **正常使用**: 提交后可正常访问系统其他功能

### 状态检查逻辑

- `none`: 没有员工信息记录 → 跳转入职页面
- `draft`: 草稿状态 → 跳转入职页面
- `submitted`: 已提交 → 正常访问系统
- `boss`（BOSS）: 不检查员工档案 → 直接进入经营看板

## 页面功能详解

### 员工数据页面 - 离职管理 Tab

**主要功能**:

- 上传、替换和删除五类 PDF（便携式文档格式）离职模板；扩展名、媒体类型或文件头不正确时拒绝上传
- 五类已上传模板均可在浏览器独立新窗口中在线预览；当前 PDF（便携式文档格式）直接显示，历史 DOCX（开放 XML 文字处理文档）临时转换后显示
- 历史 DOCX（开放 XML 文字处理文档）在线编辑继续使用未改写原稿的固定页面底图
- 为员工创建离职人员记录并查看档案完成度
- 离职管理页签的待办数字由统一待办接口直接统计“档案待完善”和“待确认离职”，登录进入系统后即显示，不依赖先点击页签
- 离职人员列表同时展示员工入职日期和在职状态，区分在职、实习期及已离职
- 当前 PDF（便携式文档格式）和历史 DOCX（开放 XML 文字处理文档）模板均可打开原版式在线编辑器，可分别下载生成文件或一并打印
- 系统按最早劳动合同开始日期填充首次签约时间；离职日期取管理员创建离职人员时选择的日期，任职年限按完整自然月自动计算
- 单独上传五类 PDF（便携式文档格式）档案，或一键识别合并 PDF（便携式文档格式）
- 档案未齐全时可删除错传文件；档案齐全并完成离职后只允许替换

### 员工数据页面 - 离职档案 Tab

**主要功能**:

- 在员工详情弹窗中于“人事档案”后新增“离职档案”Tab
- 与离职管理复用同一套五类档案组件，展示完成度和当前版本文件
- 支持单独上传、替换、预览、下载，以及合并 PDF（便携式文档格式）一键识别入位
- 管理员补录历史离职员工时，上传文件保持原样，不覆盖或重写文件内容

**相关接口**:

- `GET /api/employees/:id/resignation-archive` - 获取员工离职档案聚合数据
- `GET /api/resignation/requests/:id/documents/:docId/download` - 下载/预览离职附件

**展示规则**:

- 无离职人员记录时显示空档案，并引导管理员先在离职管理中创建
- 只展示 `is_current=1` 的当前版本；替换文件保留历史记录但不在当前档案中回退展示

### 转正申请页面（用户端）

**路由**: `/probation`（状态与历史）、`/probation/application`（独立填写）

**主要功能**:

- **状态摘要**：显示入职日期、试用期截止日期、剩余天数、当前签署阶段和各环节签署状态
- **独立页面**：员工在转正状态页点击“申请转正”后进入完整页面填写，取消或提交后返回转正页，不再使用弹窗
- **原始模板**：独立填写页面直接渲染管理员最新上传的转正申请单 PDF（便携式文档格式），不再使用系统自行绘制的详情表代替申请单
- **自动信息**：申请人、所属部门、岗位职务、入职日期和转正定岗由系统读取员工档案，并回填在原模板对应位置
- **在线填写**：员工在原模板中选择正常、提前、延期或其他转正类型，并在本人述职区域填写内容；选择“其他”时，说明输入层保持透明，原模板下划线始终可见
- **本人签名**：员工点击“签名”调用个人设置中已保存的签名，系统在签名栏按比例放大预览；未保存时提示先到个人设置上传，提交成功前由服务器二次处理，成功后记录申请日期
- **提交后查看**：当前申请进入签署中后，员工可从状态页打开只读申请单；页面读取提交时保存的姓名、部门、职位、入职日期和签名，不受员工档案后续修改影响
- **正式文件**：最终签名后系统生成待盖章 PDF（便携式文档格式）底稿；管理员打印盖章并在员工转正档案上传后，员工页面才显示该正式盖章文件
- **待签任务**：总经理处理主管领导意见；指定管理员处理人事部意见；指定董事长处理最终审批
- **审批流程**：员工状态页和审批任务页均展示员工提交、主管领导意见、人事部意见、董事长审批四个节点；每一版申请固定保存各环节具体审批人，后续角色换人不改写历史
- **历史审批**：员工和审批人均可查看全部申请版本的处理结果、签名人、实际操作人、审批意见或驳回理由及处理时间；管理员重置为实习期并重新发起后，上一轮流程继续显示在历史转正记录中
- **流程操作**:
  - 转正前默认状态显示为“实习期”
  - 主管领导意见签名之前员工可以撤回并继续修改；签名后不能撤回
  - 任一审批环节驳回前必须在当前意见栏填写驳回理由；未填写时前端提示且后端拒绝处理
  - 驳回后回到员工填写阶段，员工修改述职并重新签名后形成新版本
  - 页面展示当前版本四个环节的签署人、意见、决定和签署时间
  - 已完成记录不可修改、撤回或覆盖正式文件

**状态流转**:

```
员工独立页填写 → 总经理签主管领导意见 → 管理员签人事部意见 → 董事长签最终审批 → 已转正
                                      └──── 任一环节驳回 ────→ 员工修改并生成新版本
```

### 转正管理页面（管理端）

**路由**: 管理员、超级管理员、董事长 `/employee-data?tab=probation`；总经理 `/gm-probation-approval`

**权限**: 管理员和超级管理员在员工数据的转正管理中处理人事部意见；董事长同样在员工数据中完成最终审批；总经理只在左侧人力资源区审批中心处理主管领导意见

**主要功能**:

- 董事长完成最终审批后自动生成转正结论和待盖章底稿，并将员工状态更新为在职；缺少最终签名时生成服务直接拒绝
- 待盖章底稿在管理员审批详情中提供预览、附件下载和浏览器打印入口，并明确提示盖章后到员工转正档案上传

- 正式盖章文件上传成功后，转正申请列表的“正式文件”列立即读取同一档案记录；未上传时显示“待上传盖章件”

### 请假管理页面

**路由**: `/leave`

**主要功能**:

- `/leave` 仅展示本人假期余额、请假申请表单、申请记录和驳回重提提醒
- 总经理在 `/gm-probation-approval` 的“请假审批”页签处理普通员工申请；董事长在 `/employee-data?tab=leave` 的“请假审批”页签处理总经理申请，两处均提供本人待办、审批记录、申请详情和审批进度
- 管理员和超级管理员在 `/employee-data?tab=leave` 的“抄送记录”页签查看全员记录、附件和审批进度，不提供审批操作
- 员工可在“单一请假”和“组合请假”之间切换；固定额度假期支持按当前可用余额一键请满；组合请假的新分段天数默认为空，选择固定额度类型时自动带入完整可用余额，选择不限额度类型时由员工自行填写，不预填 `0.5` 天；尚未手动选择结束时间时，分段合计变化会按节假日和补班表自动计算结束日期及结束时段；员工手动选择或调整结束日期、结束时段后，请假时长以选定时间段为准，新增类型、修改分配天数或按余额填满均不再改变时间段，只提示还需分配或超出的天数
- 组合申请在同一事务中提交，任一段类型无效、附件缺失、余额不足、时间重叠或分配天数不一致时整组回滚；已选分段会标记需要证明文件的假期，上传区按组合内容明确列出具体假期名称，病假同时提示上传三甲医院病历或假条
- 已批准申请提供“续假”和“补假”，两者均可选择单一或组合申请：续假必须紧接主申请或上一条续假的首个工作半天，开始日期和开始时段由系统计算并锁定；补假可补录过去日期，但必须位于主申请结束之后
- 组合续假、组合补假支持 2 至 8 种假期，按员工填写的分段天数自动计算且允许调整结束时间；提交后在同一事务中拆成独立申请，共享组合批次并统一挂在原主申请下，各自审批、记账和保留证明文件
- 续假、补假统一通过 `parent_request_id` 挂在主申请下；审批列表直接展示“组合续假”或“组合补假”及原假期摘要，详情展开显示原申请编号、类型、时间、天数、状态及事由；原申请、组合申请和同一主申请下的其他记录均可直接点击查看，并支持返回上一申请，无需另行按编号查找；驳回重提继续使用独立版本链，组合续假分段重提时锁定原分段开始时间
- 婚假按员工基础信息中的身份证号执行一次性资格锁定：同一身份证号存在审批中或已批准婚假后，普通请假、组合请假、续假和补假均不能再次选择婚假；驳回或取消的婚假不占用资格，身份证号缺失时须先完善基础信息
- 审批记录按实际操作的总经理或董事长展示；同一申请经历驳回、重新提交和通过后只展示当前最终版本，完整过程保留在详情中
- 审批记录中的审批时间完整显示到秒，并固定在同一行展示
- 驳回必须填写理由；指定审批人也不能通过或驳回本人申请
- 请假记录中的已批准申请展示距返岗的自然天数（支持半天）及精确返岗时段；普通组合请假、组合续假和组合补假全部分段通过后，各分段统一按整组最后一个结束时段显示返岗时间，仍有未通过分段时不提前计入；已结束申请显示“已返岗”
- 取消请假申请（待审批状态）

**请假类型**:

- `annual`: 年假
- `personal`: 带薪事假
- `sick`: 病假
- `compensatory`: 调休假/丧假（以后台配置名称为准）
- `marriage`: 婚假
- `maternity`: 产假
- `paternity`: 陪产假
- `other`: 其他请假（不限额度）

**余额同步规则**:

- 年假、带薪事假、病假、丧假、婚假、产假和陪产假固定启用余额检查；管理员可调整类型默认天数，也可在员工余额表中调整个人年度总天数
- 不限额度类型不显示无意义的 0/0 余额，员工看板和管理员余额表统一显示“不限额度”
- 管理员修改假期类型默认天数时，后端会同步当年仍等于旧默认天数的余额记录
- 已由管理员手动调整为其他数值的个人余额不会被默认天数变更覆盖
- 2026 年历史 `personal` 余额中仍为 999 天的记录已修正为当前配置的 3 天

**状态流转**:

```
草稿 (draft) → 待审批 (pending) → 已批准 (approved)
      ↑               ├→ 已拒绝 (rejected) → 修改后生成新版本并重新提交
      └──── 撤回 ─────┘

草稿 → 申请人手动永久删除
     → 月度切换后系统自动永久删除

已批准主申请 ──续假──> 独立待审批申请（紧接上一段工作时段）
             └─补假──> 独立待审批申请（允许补录历史日期）

组合请假 ──同一事务拆分──> 申请一 + 申请二 + ...（分别审批、分别记账）
组合续假/补假 ──同一事务拆分──> 多条独立申请（共享组合批次并关联同一主申请）
```

- 撤回后立即释放审批中占用的假期余额，申请编号和完整审批历史保留在同一条申请中
- 草稿重新提交时重新校验日期、时间重叠、余额、证明附件和当前审批人
- 手动删除与月底自动删除均为硬删除，整条版本链、审批日志、附件记录和磁盘文件一并清理
- `cancelled` 仅兼容旧备份；服务启动后会将旧“已撤销”记录自动迁移为草稿，新撤回统一进入 `draft`

- 审批流程按“角色 姓名”显示当前及历史处理人；待处理节点使用申请提交时的审批人快照，已处理节点使用签署记录中的实际操作人姓名，因此后续更换审批人不会改写历史
- 转正提交、审批、签署、生成和归档时间在数据库中保留统一时间，页面统一转换为北京时间显示
- 最终审批通过并成功生成待盖章底稿后，员工状态自动变为“在职”；正式盖章件由管理员后续归档

**关键数据一致性规则**:

- 每名员工最多保留一条当前转正记录，数据库通过员工编号唯一索引兜底
- 合同档案、员工入职日期、合同到期日期和待处理转正记录在同一事务内同步
- 跨年请假按各自然年的实际工作日分别预占余额，审批、驳回和撤销使用提交时快照结算
- 管理员不能将假期总额调低到已使用天数与审批中天数之和以下
- 五类离职档案上传完成后先供管理员预览核对；管理员确认离职时，员工已离职状态、离职记录完成状态、原账号停用和审计日志使用同一事务
- 离职档案由后端校验为真实 PDF（便携式文档格式）；模板由后端校验为真实 DOCX（开放 XML 文字处理文档）

## 权限控制

当前实际权限配置：

- **普通员工**: 填写本人入职档案，提交本人转正和请假申请；不使用离职页面
- **管理员**: 管理员工档案、人事模板、离职归档、请假配置和余额；以抄送身份查看全员请假流程但不能审批；在转正流程中从“员工数据 > 转正管理”签署本人负责的人事部意见
- **总经理**: 在转正流程中签署主管领导意见，并在人力资源审批中心处理分配给本人的请假申请；只有同时具备管理员权限时才能办理离职归档
- **超级管理员**: 系统最高管理角色，具备管理员的人事操作能力，可管理档案、工资、请假配置和离职；请假流程中仍只作为抄送对象，不能审批
- **董事长**: 具备系统管理页面权限，在“员工数据 > 转正管理”使用本人签名完成最终审批，并在“员工数据 > 请假管理”审批总经理请假；人力资源区不显示独立审批中心
- **BOSS**: 仅查看经营看板，不建立员工档案，不进入员工统计、同事选择、假期余额、工资生成和人力成本
- **系统专用账号**: 超级管理员、董事长和 BOSS（老板）本人不参加员工转正，不出现在转正列表、统计、待办目标、本人转正状态或转正档案；其查看及审批真实员工转正的管理权限保持不变
- **请假审批人**: 普通员工提交时选择活动状态的总经理，总经理提交时选择活动状态的董事长，并始终排除申请人本人；缺少对应角色的可用审批人时不允许提交
- 系统当前没有独立“人力资源专员”角色，也不能仅凭职位名称获得审批权限

## 注意事项

1. **日期计算**: 请假天数需要考虑工作日和节假日
2. **试用期日期**: 以第一份劳动合同识别出的开始日期和试用期截止为准，不按固定月数推算，续签不覆盖
3. **数据一致性**: 员工状态需要与入职、转正、离职流程保持同步
4. **审批权限**: 转正由总经理处理主管领导意见、管理员处理人事部意见、董事长处理最终审批；普通员工请假由申请单指定的总经理处理，总经理请假由申请单指定的董事长处理，管理员和超级管理员在员工数据中只查看抄送记录；离职由管理员归档，不再走审批流程
5. **数据归档**: 离职完成后可替换错传文件，但不能删除到不完整；历史版本保留

## 收款信息同步

### 功能说明

付款审批中心的收款人信息与入职填写的基础信息中的收款信息保持一致。用户在入职页面填写收款信息后，管理员在付款页面可以直接看到该用户的收款信息。

### 数据来源

收款人信息优先从 `employee_profiles` 表获取（入职时填写的信息），如果入职信息中没有收款信息，则回退到 `users` 表（兼容旧数据）。

### 相关 API

- `GET /api/approval/payee-info/:userId` - 获取收款人信息
  - 优先从 `employee_profiles` 表获取
  - 回退到 `users` 表（兼容旧数据）

### 收款信息字段

| 字段                | 说明         |
| ------------------- | ------------ |
| bank_account_name   | 收款人姓名   |
| bank_account_phone  | 收款人手机号 |
| bank_name           | 开户行       |
| bank_account_number | 银行卡号     |
