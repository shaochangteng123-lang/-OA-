# 06 - 路由与布局模块

## 模块概述

路由与布局模块负责应用的页面路由管理、导航守卫、页面布局框架和权限控制。

## 主要功能

### 1. 路由管理

- 页面路由配置
- 懒加载优化
- 路由元信息管理
- 动态路由生成

### 2. 导航守卫

- 登录状态检查
- 权限验证
- 页面访问控制
- 重定向逻辑

### 3. 布局系统

- 主布局框架
- 侧边栏导航
- 顶部导航栏
- 面包屑导航

### 4. 页面切换

- 路由过渡动画
- 页面加载状态
- 错误页面处理

## 羽隶经营看板布局

- `/boss-dashboard`（羽隶经营看板）仅允许BOSS、管理员和超级管理员访问。
- BOSS不需要填写入职资料，登录后由导航守卫直接进入经营看板。
- BOSS侧边栏只展示经营管理和个人设置，不展示普通业务操作区与审批中心。
- BOSS没有业务待办，主布局不为BOSS启动待办轮询。
- BOSS直接访问入职页或普通业务页面时自动返回经营看板。
- 看板首屏采用浅色、紧凑的经营驾驶舱布局，顶部集中展示名称、所选财务周期、数据质量、更新时间、当前状态摘要和周期选择，不再使用大面积深色首屏。
- 首屏下方提供“经营概览”“财务分析”“人员与日志”“项目与风险”四个互斥分区；任一时刻只渲染当前选择的分区，不再把所有图表、人员、日志、项目和风险纵向堆叠在同一个总览中。
- 按月时选择一个自然月，按年时选择一个自然年；周期控件只改变财务指标、趋势和报销明细。人员、日志、项目和风险分区明确展示当前实时快照，不冒充所选历史周期。
- 看板保留手动刷新、全屏查看、最后更新时间、同步倒计时和每 30 秒静默自动刷新。

### 路由元信息

```typescript
interface RouteMeta {
  title?: string; // 页面标题
  requiresAuth?: boolean; // 是否需要登录
  permission?: string; // 所需权限
  roles?: string[]; // 允许的角色
  icon?: string; // 菜单图标
  hidden?: boolean; // 是否在菜单中隐藏
  breadcrumb?: boolean; // 是否显示面包屑
}
```

## 导航守卫

### 全局前置守卫

```typescript
router.beforeEach(async (to, from, next) => {
  const authStore = useAuthStore();

  // 设置页面标题
  document.title = to.meta.title
    ? `${to.meta.title} - YuliLog`
    : "YuliLog 工作日志系统";

  // 检查是否需要登录
  if (to.meta.requiresAuth && !authStore.isAuthenticated) {
    return next({ name: "Login", query: { redirect: to.fullPath } });
  }

  // 检查权限
  if (to.meta.permission && !authStore.hasPermission(to.meta.permission)) {
    ElMessage.error("您没有访问该页面的权限");
    return next({ name: "Home" });
  }

  next();
});
```

### 全局后置守卫

```typescript
router.afterEach((to, from) => {
  // 页面切换后的操作
  // 例如：关闭加载状态、记录访问日志等
});
```

### 侧边栏导航

- 菜单项根据权限动态显示
- 支持多级菜单
- 当前路由高亮显示
- 可折叠/展开
- 当前用户的劳动合同进入到期前 10 天或已经到期时，“入职”菜单显示红色角标，人力资源分组同步显示红点；已离职员工不提示
- 管理员或超级管理员存在试用期截止 30 天内或已到期的待处理员工时，“员工数据”菜单显示红色角标，人力资源分组同步显示红点
- 总经理存在待签署的主管领导意见或普通员工请假待办时，人力资源区“审批中心”显示任务总数；董事长的转正终审、总经理请假、离职及试用期相关待办统一计入“员工数据”角标，管理员和超级管理员的员工数据角标不计入只读抄送记录
- 员工请假审批通过后，主布局在待办轮询中弹出成功通知，“请假”菜单与人力资源分组显示未读角标；员工进入请假页关闭通过提示后清除未读数量

### 月度财务报表菜单与路由

- “月度财务报表”保留在现有“财务区”分组，并排列在当前角色可见的“审批中心”正下方，不新建一级分组。
- 菜单可见性使用 `canViewMonthlyFinancialReport`，只在角色为 `admin`（管理员）或 `general_manager`（总经理）时返回真值。
- 页面路由为 `/monthly-financial-report`，`meta.requiresRole` 精确设为 `['admin', 'general_manager']`。
- `super_admin`（超级管理员）、`chairman`（董事长）、`boss`（经营管理）和 `user`（普通员工）不显示菜单，直接地址访问也会被路由守卫拒绝。
- 管理员和总经理进入同一页面；操作按钮再依服务端返回的权限细分。管理员可维护、同步、月结、重新开启和下载；总经理仅可查看和下载。
- 页面顶部收入卡片显示“当月实际到账合计”，只表示已确认主营业务银行回款总额；“四账户净变化”明确为账户期末减期初，避免把税费拆分后的账户流入误解为银行到账。
- 管理员存在未保存的期初或手工项目时，重新加载、月份路由变化、离开页面和浏览器刷新统一提示确认；加载失败保留当前报表和草稿。并发版本冲突不再自动刷新覆盖本地内容；保存、同步、月结和重开响应按月份与视图序号校验，旧月份响应不能覆盖当前页面。

#### 菜单结构（自上而下）

1. **办公区**
   - 日历
   - 今日日志
   - 历史日志

2. **财务区**
   - 基础报销
   - 大额报销
   - 商务报销
   - 报销统计
   - 报销管理（仅管理员）
   - 审批中心（管理员、总经理按各自入口显示）
   - 月度财务报表（仅管理员、总经理，紧邻审批中心下方）

3. **人力资源**
   - 入职
   - 转正
   - 请假
   - 审批中心（仅总经理）
   - 员工数据（管理员、超级管理员、董事长）

“转正”页面只展示当前员工本人的申请状态、申请单和历史记录，不承载任何审批任务。总经理从人力资源区“审批中心”签署主管领导意见；管理员和超级管理员从“员工数据 > 转正管理”签署人事部意见；董事长同样从“员工数据 > 转正管理”进入本人负责的转正终审。`/gm-probation-approval` 仅允许总经理访问。
“请假”页面只展示当前员工本人的余额、申请和历史记录，不承载审批任务。总经理从人力资源区“审批中心 > 请假审批”处理普通员工申请；董事长从“员工数据 > 请假管理 > 请假审批”处理总经理申请并查看本人审批记录；管理员和超级管理员在同一管理页只显示“抄送记录”，不显示审批入口或请假待办角标。
离职不再作为员工侧菜单窗口；管理员和超级管理员从“员工数据 > 离职管理”进入。历史 `/resignation` 地址仅对管理员开放，并重定向至 `/employee-data?tab=resignation`。

4. **合同管理（独立模块，位于人力资源下方）**
   - 合同台账（管理员、超级管理员、董事长、总经理、普通员工）
   - 合同经营看板（管理员、超级管理员、董事长、总经理）
   - 合同审批（仅总经理）
   - 我的申请（仅普通员工；包含合同下载申请、开票及用印申请）
   - 下载申请审批（仅总经理）
   - 合同下载待办（仅被指定的管理员）

合同管理使用独立侧边栏分组。普通员工可查看具体行政区合同台账，并从单一“我的申请”入口切换查看合同下载申请和开票及用印申请，不显示经营看板或合同审批；本人下载结果未读及被驳回待修改的开票申请计入“我的申请”和合同管理分组提示。总经理的合同审批、下载审批、开票审批分别显示数字角标并汇总到合同管理分组。管理员、超级管理员和董事长不显示合同审批；管理员合同待办持续统计待盖章、待开具以及已开具但尚待财务登记的任务，直至流程完成。一级分组标题只显示是否存在待办的红点，具体数量仅在二级业务菜单显示。BOSS（经营管理）账号继续从专属分组只读访问台账和看板，服务端排除区域为“全部”的合同。

合同台账筛选包括关键字、合同分类、生命周期状态、结算状态、项目、区域、合同关系、相对方、合同日期、页码和每页数量；结算状态承接经营看板的未结算、部分结算、已结清卡片下钻。电脑端全部筛选项与查询操作保持同一行，可用宽度不足时仅在筛选区内部横向滚动，移动端改为单列。台账表格在合同信息前显示跨分页连续序号，表头与内容统一居中并保持单行展示。合同经营看板筛选包括年份、月份、合同分类和项目。筛选值同步到 URL（统一资源定位符）查询参数，刷新页面、复制地址以及浏览器前进后退时均恢复同一查询状态。

合同台账“合同截至日期”只在主合同已完成，或主合同已有有效财务回单后终止时显示；取整条根合同最后一笔已确认未冲正回单业务日期。生效中、执行中、待签合同和所有补充／解除协议关联行统一显示“—”。

新增合同页在文件选择区之前展示北京市 16 个行政区选择器和主营／非主营／资产三类预选卡片；未完成两项必选时，文件选择、拖拽和上传按钮均禁用。选择资产类后还必须从采购、软件、设备、房屋租赁、汽车租赁、车位合同、办公资产七类中选择资产子类。上传成功后生成 `HT-YYYYMMDD-######` 编号和草稿，并锁定 `area`（行政区）、`declared_category`（预选分类）及资产子类。预选分类只用于校验 OCR（光学字符识别）的合同类型是否一致，绝不能替代、预填或覆盖 OCR 合同类型。

识别过程与页面加载状态分离，第二步只读展示系统结果：甲方、乙方、项目名称、合同金额、合同类型和合同签订日期六个核心字段未舍入的最终验证值必须全部严格为整数 100，并通过独立证据、字段内及跨字段验证后才可进入下一步。99.99、99.999 及任何小于 100 的值均失败，页面不得通过四舍五入或格式化冒充 100；整数 100 只是必要条件，内容错误或冲突仍然失败。任一字段或验证失败时，系统原子不写六字段，不显示人工填写、校验、修改或补录入口，并提示重新识别或重新上传清晰完整的合同。草拟合同签订日期不得用上传日期、当前日期或推测值回填。草稿详情提供二次确认删除，目标审批人尚未处理本轮审批时允许发起人或财务撤回。离开未提交向导前显示提示，避免误以为本地修改已经提交。

项目关联区只加载 `worklog_projects.district`（项目行政区）与上传时锁定行政区相同的项目。选择同区项目只设置项目关系，不改变合同区域；客户端伪造异区项目或项目区域在并发期间变化时，服务端拒绝保存，不得覆盖合同 `area`。补充协议或终止协议只能选择同区且分类、资产子类一致的上级合同；上级合同不得覆盖当前行政区、预选分类或 OCR 合同类型。未关联项目的非主营或资产类合同继续使用上传前锁定行政区，第三步不再提供行政区选择。

合同详情根据状态联动业务按钮：草拟中显示编辑、删除和提交；审批中且本轮未处理时可由有权限人员撤回；待盖章显示盖章版核验；生效中或执行中显示财务录入；已完成不显示新增财务入口。合同台账不提供行级通过、驳回或审批签名动作，“待审批合同”指标继续导航到合同审批中心；审批中心是集中查看待办和已处理记录的入口。当前账号等于本轮锁定目标审批人时，合同详情顶部固定展示“驳回”和本轮通过操作；总经理首次用印时通过操作显示“审批并签名”。顶部操作区位于页签容器之外，因此切换合同总览、合同关系、审批流程、合同附件或财务闭环等任一页签后仍可直接处理，不在审批流程页签重复展示第二组操作。合同附件在页签内按合同、发票、回单、用印申请单四组排列，只渲染非空组并在组标题显示数量；回款与付款回单归入同一组，未知及其他已归档类型回退合同组。页签总数继续使用原展示附件总数，分组不合并财务闭环或辅助档案数据。点击审批操作后在详情当前页面复用 `ContractApprovalWorkspace`（合同审批工作区）；非目标审批人不显示入口，工作区执行函数也会再次校验目标账号和审批中状态。审批人（包括总经理）从合同审批中心点击“查看详情”时，统一先进入“合同总览”页签，并保留待处理／已处理来源页签用于返回；不会自动跳到“审批流程”。详情左上角按来源显示“返回审批中心”。详情已发生节点展示真实操作时间、操作名称与“职位 姓名”，当前唯一的“等待职位 姓名审批”节点显示“待处理”。总经理点击“审批并签名”后进入专注签署状态，详情摘要、执行指标、生命周期和业务页签暂时隐藏；页面只保留当前单页用印申请单、可点击的总经理审批签署区和底部操作，不重复展示合同名称／金额摘要、工作区说明、审批意见、冗长签名提示或多层同义标题。总经理点击签署区后，系统在申请单右侧审批栏同一区域显示本人已锁定电子签名和“待提交”状态，并禁用签署区以避免重复请求。未完成签名确认、签名未锁定或签名／申请单加载失败时，“确认审批并签名”保持禁用；只有本人签名已确认且所有必需资料就绪后，才可提交审批与落签。成功后工作区继续保留，并切换为 `approvedFileId`（最终双签文件编号）对应的最终单页双签申请单，待本人核对后手动关闭；详情在工作区保留期间不提前刷新或隐藏双签结果。合同详情不再提供操作审计页签或前端审计请求，后台安全留痕仍保留。财务记录以草稿、已确认、已冲正三态展示，只有草稿显示确认／删除，只有已确认显示冲正。

合同附件页签只在主合同详情显示，集中汇总同根主合同、补充协议和解除协议附件；补充及解除协议详情隐藏该页签。页面先按合同、发票、回单、用印申请单四类分组；合同、回单和用印申请单继续按来源合同分层，主合同在前、补充协议按序号升序、解除协议在后，每层标题显示来源标签、来源名称和数量，每个来源分别保留一个当前用印申请单。发票由主合同财务登记统一归档，在发票组直接集中展示，不再标注主合同／补充协议来源。页签总数使用聚合后实际展示文件数，文件卡片仍复用既有按角色预览／下载操作，且不读取财务闭环或辅助档案数据。

从合同详情的“合同关系”进入另一份主合同、补充协议或解除协议时，新详情记录上一个合同页面，左上角显示“返回上一个页面”。返回原审批合同后继续保留“返回审批中心”及原待办／已处理来源，不会错误跳至合同台账。

合同详情“财务闭环”的发票表格将销售方名称固定在单元格内，开票名称和超长发票号码完整换行展示。财务工作区统一改为纵向三阶段：发票、经营支出回单、最终对外付款。资产合同链条图顶部显示可供财务确认的资金承担方式：工程咨询直接付款、工程咨询划拨科技支付、科技自行承担或待核对。内部划拨模式下，工程咨询向科技的回单按付款日期计入工程咨询经营支出；科技向房东／供电方／物业方的最终付款只核销履约，不再重复增加支出。所有链条节点保持白色背景，只使用状态标签表达待划拨、待对外付款和已闭环。

盖章核验弹窗同时展示审批快照、只读识别值、未舍入最终验证值和差异。甲方、乙方或金额的最终验证值不严格等于整数 100、字段缺失、内容错误或发生候选冲突时整次核验不通过，只提供重新识别或重新上传，不提供逐字段人工确认和补录；盖章版合同日期无法识别时按原始业务规则自动采用上传日期并标明来源，但该兜底值不是 OCR 100，不得在页面或审计中冒充。此回退规则不适用于草拟合同。可靠识别结果与审批快照存在差异时，要求财务填写说明，并按“已关联项目的主营合同由项目负责人、未关联项目及其他合同由唯一活动总经理”的规则重新锁定本轮复审人；复审通过后才出现最终归档入口。

## 注意事项

1. **路由命名**：
   - 所有路由必须设置唯一的 `name`
   - 便于编程式导航和路由跳转

2. **权限控制**：
   - `meta.permission` 与后端权限保持一致
   - 前端权限检查仅用于 UI 展示
   - 后端必须有对应的权限验证
   - `/users` 使用管理员路由守卫；后端 `/api/users` 仍独立校验数据库中的实时角色

3. **懒加载**：
   - 大型页面组件必须使用懒加载
   - 避免首屏加载过大的 bundle

4. **路由嵌套**：
   - 保持路由层级简洁
   - 避免过深的嵌套层级

- `/contract-applications/mine`：普通员工统一“我的申请”页面，以按需挂载页签切换“合同下载申请”和“开票及用印申请”；未打开的下载页签不会误确认结果已读。开票页签内再区分“当前申请／历史申请”：草稿、审批中、驳回待修改、待盖章和待开票属于当前申请，流程已完成的记录进入历史申请；两类列表均显示跨分页连续序号。
- `/invoice-applications/new`：员工发起或通过查询参数继续编辑本人草稿。主营合同首先只展示三联单上传，安全识别“其他费用”工作表本次付款合计后，再显示开票资料、签名和提交区域。
- `/contract-download-requests/mine`、`/invoice-applications/mine`：保留为兼容地址，分别重定向至统一页面的下载、开票页签并保留原查询参数。
- `/invoice-applications/approval`：采用与合同审批一致的渐变工作台页头、当前视图数量、刷新、服务端搜索和“待我审批／审批记录”页签。待办只显示提交时锁定给当前总经理且尚未处理的开票申请；审批记录显示当前总经理本人已经通过或驳回的申请，并保留后续流程状态。两个页签的内容均显示跨分页连续序号。侧边栏二级菜单显示数字角标，一级“合同管理”分组只显示红点。
- `/invoice-applications/tasks`：管理员处理待盖章交付、已开具登记和待财务登记任务。主营三联单的主操作只调用“打印”接口，不使用完整原件代替“其他费用”工作表打印件；只有完成“登记已开具”后才显示前往合同财务登记上传正式发票的入口。

三类工作台共用同一状态展示组件，但操作按钮严格按登录人角色和当前状态显示。管理员只执行盖章交付和开具登记，不显示审批按钮。
