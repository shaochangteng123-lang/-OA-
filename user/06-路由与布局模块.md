# 06 - 路由与布局模块

## 董事长福利1、福利2报销入口（2026-09-09，已上线）

财务区在“商务报销”下方依次为董事长显示“福利1报销”和“福利2报销”。福利2列表、新建和详情分别使用 `/welfare-two-reimbursement`、`/welfare-two-reimbursement/create` 和 `/welfare-two-reimbursement/:id`，与福利1相同，仅董事长可进入列表和新建页，管理员可从审批中心进入详情。两类福利报销均复用大额报销布局且不应用1000元门槛；福利1使用紫色主题，福利2使用柔和玫瑰色主题。付款和批量付款路由继续采用精确角色校验，只允许管理员和超级管理员进入。报销管理提供“报销范围／福利1分类／福利2分类”三个页签。

## 一般账户出账默认总金额（2026-09-09，已上线）

出账折线首次进入固定默认“总金额”，即使全部未知也不自动跳至行政；用户手动切换后刷新保持其选择。点击总金额或任一分类点位，均显示对应真实期间的行政、薪资、一般账户跨行手续费、实际税费、资产五类饼图；总金额不作为第六片。分类未知时点位和圆心明确“已知部分”，上方银行实际支出摘要保持独立。

生产仅替换当前活动财务页面脚本和财务分析服务；主入口、样式、其他页面及其余六个分析模块保持原生产文件。最终压缩页面已验证月度、季度、年度默认总金额、点位联动和旧缓存刷新；生产切换前后55张相关业务表内容一致。

## 三处报销月份统一（2026-09-08，已上线）

行政支出、商务统计、人力成本中的报销均按系统报销月份展示。一般账户结构图因同时保留银行实际资金总额，中心改为“银行实际支出”，提示行政报销月份与银行交易日期不作月度闭合比较；标题不再误称为同一口径占比。商务点选、区域构成和人力点位使用同一报销月份来源，回单上传月份不改变显示。

## 一般账户出账选择器调整（2026-09-08，已上线）

按接口的图表指标白名单显示五类出账，单指标、多指标、本期和同期统一移除业务支出、一般账户总支出及已录入部分。总额仍作为账户摘要和结构图中心核对数据；不与分类重复累计。过滤序列保留稳定引用，点选明细不因父组件重新渲染而清空。旧接口没有白名单时兼容原响应，新接口始终给出明确五类。

## 住房分摊最新口径（2026-09-07，已上线）

人员明细和导出以各住房合同全部已上传并确认的有效发票为基数，按完整实际租赁天数分到各月，当前月截至当天。明确提示新发票会更新全租期基数、未到期份额留在后续期间，不再显示旧的合同月费计提及变量收费月份口径；旧、新合同独立分摊后按月合并。历史版本日志保留，不代表当前开发口径。

## 羽隶经营看板布局

- `/boss-dashboard`（羽隶经营看板）仅允许BOSS、管理员和超级管理员访问。
- BOSS不需要填写入职资料，登录后由导航守卫直接进入经营看板。
- BOSS侧边栏只展示经营管理和个人设置，不展示普通业务操作区与审批中心。
- BOSS没有业务待办，主布局不为BOSS启动待办轮询。
- BOSS直接访问入职页或普通业务页面时自动返回经营看板。
- 看板首屏采用浅色、紧凑的经营驾驶舱布局，顶部集中展示名称、所选财务周期、数据质量、更新时间、当前状态摘要和周期选择，不再使用大面积深色首屏。
- 首屏下方提供“经营概览”“财务分析”“人员与日志”“项目与风险”四个互斥分区；任一时刻只渲染当前选择的分区，不再把所有图表、人员、日志、项目和风险纵向堆叠在同一个总览中。
- 按月时选择一个自然月，按年时选择一个自然年；周期控件只改变财务指标、趋势和报销明细。人员、日志、项目和风险分区明确展示当前实时快照，不冒充所选历史周期。
- 看板保留手动刷新、全屏查看、最后更新时间、同步倒计时和每 30 秒静默自动刷新。

## 导航守卫

### 全局前置守卫

```typescript
router.beforeEach(async (to, from, next) => {
  const authStore = useAuthStore();

  // 设置页面标题
  document.title = to.meta.title
    ? `${to.meta.title} - YuliLog`
    : "YuliLog 工作日志系统";

  // 检查是否需要登录
  if (to.meta.requiresAuth && !authStore.isAuthenticated) {
    return next({ name: "Login", query: { redirect: to.fullPath } });
  }

  // 检查权限
  if (to.meta.permission && !authStore.hasPermission(to.meta.permission)) {
    ElMessage.error("您没有访问该页面的权限");
    return next({ name: "Home" });
  }

  next();
});
```

### 月度财务报表菜单与路由

- 2026-09-07 本轮开发中的住房全成本展示：人力明细使用“房屋租赁成本分摊”，范围是同一房屋租赁合同的租金、物业管理费、电费、系统维护费及其他已确认住房费用，不是全部资产平摊。新增“房屋租赁分摊基数（公司费用）”区，按上方已提交统计期间展示分摊前分类及费用合计；该区用于核对公司基数，不随单人筛选改成个人份额，也不得与个人费用再次相加。分类不完整时显示“已知费用合计／已知部分”，未知不补零；点位饼图仍按已选人员和实际期间联动。导出同步增加独立住房构成表。本轮尚未部署，最终页面、导出及生产验收状态见 [住房全成本分摊验收-2026-09-07.md](../docs/住房全成本分摊验收-2026-09-07.md)。
- 模块导航与标题统一命名：`inflow`（入账模块）为“一般账户入账统计”，`outflow`（出账模块）为“一般账户出账统计”，`projects`（项目模块）为“项目分析”，`business`（商务模块）为“商务统计”，`personnel`（人力模块）为“人力成本分析”。余额名称及“收支结余”导航不变；命名同步导出表名，不更改业务键、字段或计算。
- 七模块“全屏查看”统一打开整个财务分析面板，包含筛选栏、七模块导航、当前模块摘要／图表／明细及导出；不是单模块独立全屏。在全屏内点击导航即可切换七模块，全屏元素保持不变，切换不重新查询或退出，不改横向月份与筛选草稿；当前模块滚动到固定导航下方。顶部固定显示专用退出按钮，按钮及退出键可返回，停用页签、权限失效和卸载仍退出；原生不可用时使用页面铺满后备并恢复原页面滚动。
- 桌面查询栏将统计期间、统计周期、往年对比、当前模块适用的业务筛选以及查询按钮排在同一行，日期范围与所有控件保持56像素高并上下对齐；商务统计的报销范围级联器同时固定根节点、内部输入框和边框容器高度，避免因组件默认高度较小而使整组标签与方框下沉。甲方／合同区域只在入账和项目模块显示，查询按钮在行末。1000像素及以下视口使用紧凑双列布局，避免把文字压到不可读或让页面外溢。
- 七模块均提供“开启／关闭年度对比”按钮，各模块按自己的业务键独立保存显示状态；关闭只隐藏当前模块的同期曲线、金额、图例和轴注记，不影响其他模块，也不改统计查询、对比年份、摘要、明细、版本或导出。在当前页面内切换模块、浏览月份、刷新数据或进入／退出全屏后仍保留各自的选择。没有已加载同期数据或窗口加载中时按钮禁用，并提示先选择往年对比年份查询；关闭当前模块只清理自身的同期点选联动：余额回年度、出账回统计期间、项目收起同期明细，本期及其他模块选择保留。
- 账户余额资金台帐的饼图新增年度默认视图和折线点选月份视图，范围文字显示真实时点；点击当期／同期金额均联动对应来源月的四账户构成，提供“返回年度资金占比”。圆心显示精确总金额，旁列一般、商务、福利金一、福利金二账户金额和百分比；全零用中性环，未知不补零。窄屏中心及账户长金额可换行，不改动其他模块的结构图。
- 七模块主折线统一采用固定纵轴、紧凑浅底精准金额和可拖动的图形样式，并跟随已提交的统计周期：月度每屏12个月，季度每屏12个自然季度，两者均可独立滚轮／拖动浏览更早历史并整期吸附；1900年下界不足12季时只显示合法期间，截止月份所在未完季度不补未来月份。年度仍按所选范围的实际年份展示，少量期铺满、单年居中，只在已查询期间内浏览。
- 七模块折线本期为绿色实线／圆点，单指标同期为灰色虚线／方点；零点保留 `¥0.00` 并连线，未知点继续断开；多指标、负数和超长小数继续使用原始精确金额，不为图形改值。标签自动避让，拖动期间纵轴比例保持稳定；隐藏模块不根据归零的滚动位置查询，尺寸变化保持月份。其他结构图、余额专属饼图联动与各模块财务口径不变。
- “回到本月”放在七模块主折线工具栏的“多指标比较／返回单指标”右侧，两按钮保持相邻；单指标模块也可使用该快捷入口。点击后按上海业务时区恢复截至本月的最近十二个月，切回月度并立即查询，保留其他业务筛选和同比年差；即使统计范围未变也强制恢复图表月份。日期筛选区不放该按钮，普通页面和全屏共用图内入口，隐藏模块不能触发查询。
- 财务趋势页签保留七个业务模块，使用切换导航，一次只显示一块，默认账户余额；各块保留摘要、新版图表、点选明细和导出，不再显示下方“口径、来源与校验”“本期统计金额”“对比期统计金额”“来源明细”四块折叠内容，商务原独立来源列表也不挂载。数据本身及导出中的统计／来源明细保留。旧版“连续历史趋势与同期对比”仍不恢复；新版每屏12月／12季、年度对比、全屏及活动页只读刷新保持。
- 趋势首屏压缩月报标题与维护信息，同步、上传、保存、月结等维护操作不占趋势首屏，切换其他页签仍保留原入口和权限。仅保留顶层必要的数据校验提示，模块下方四个重复折叠区已移除；首屏优先显示时间条件、对比年份、模块导航和当前图形。甲方／合同区域只随入账和项目模块显示，商务范围及人员条件随对应模块显示，小屏图表在容器内滚动。
- 往年对比默认上年同期，可改为其他合法历史年份或“不对比”；选项由新版面板按统计开始年份生成，保留1900年至开始年前一年的全部合法年份，不再依赖旧趋势图发现年度。开始年份为1900时不自动选择更早年份。两期起止月份按同一年差平移，本期实线、对比期虚线按相同指标对齐，不混加金额。折线默认单指标，可切换指标或显式开启多指标比较。
- 统计期间使用独立月份范围选择器，统一日历图标、边框、悬停和焦点样式，清晰显示“开始月份／结束月份”；显示中文年月，传值仍为 `YYYY-MM`（年月格式）。仅允许 1900—2099 年，禁止清空和手输，普通模式弹层传送至文档根部，全屏时传送至财务分析全屏根节点并适配窄屏；切换前关闭旧弹层，防止原生全屏把文档外部弹层遮住。“近12个月”仅点击后以当前结束月份向前取 11 个月，越过 1900 年下界时禁用，不因挂载或父值变化自动缩短范围。
- 当前模块主折线独占整行宽度；选择月／季／年并查询成功后，同步更新横轴、趋势金额及同粒度同期对比，未提交筛选或查询等待中仍保留上一组已显示结果。月度／季度滑动不改统计及导出范围，“用当前窗口统计”才显式同步并保留所选粒度和同比年差；年度直接复用统计响应并隐藏窗口统计操作。结构图排在折线之后，不争用主图空间。

新增合同页在文件选择区之前展示北京市 16 个行政区选择器和主营／非主营／资产三类预选卡片；未完成两项必选时，文件选择、拖拽和上传按钮均禁用。选择资产类后还必须从采购、软件、设备、房屋租赁、汽车租赁、车位合同、办公资产七类中选择资产子类。上传成功后生成 `HT-YYYYMMDD-######` 编号和草稿，并锁定 `area`（行政区）、`declared_category`（预选分类）及资产子类。预选分类只用于校验 OCR（光学字符识别）的合同类型是否一致，绝不能替代、预填或覆盖 OCR 合同类型。

识别过程与页面加载状态分离，第二步只读展示系统结果：甲方、乙方、项目名称、合同金额、合同类型和合同签订日期六个核心字段未舍入的最终验证值必须全部严格为整数 100，并通过独立证据、字段内及跨字段验证后才可进入下一步。99.99、99.999 及任何小于 100 的值均失败，页面不得通过四舍五入或格式化冒充 100；整数 100 只是必要条件，内容错误或冲突仍然失败。任一字段或验证失败时，系统原子不写六字段，不显示人工填写、校验、修改或补录入口，并提示重新识别或重新上传清晰完整的合同。草拟合同签订日期不得用上传日期、当前日期或推测值回填。草稿详情提供二次确认删除，目标审批人尚未处理本轮审批时允许发起人或财务撤回。离开未提交向导前显示提示，避免误以为本地修改已经提交。

项目关联区只加载 `worklog_projects.district`（项目行政区）与上传时锁定行政区相同的项目。选择同区项目只设置项目关系，不改变合同区域；客户端伪造异区项目或项目区域在并发期间变化时，服务端拒绝保存，不得覆盖合同 `area`。补充协议或终止协议只能选择同区且分类、资产子类一致的上级合同；上级合同不得覆盖当前行政区、预选分类或 OCR 合同类型。未关联项目的非主营或资产类合同继续使用上传前锁定行政区，第三步不再提供行政区选择。

合同详情根据状态联动业务按钮：草拟中显示编辑、删除和提交；审批中且本轮未处理时可由有权限人员撤回；待盖章显示盖章版核验；生效中或执行中显示财务录入；已完成不显示新增财务入口。合同台账不提供行级通过、驳回或审批签名动作，“待审批合同”指标继续导航到合同审批中心；审批中心是集中查看待办和已处理记录的入口。当前账号等于本轮锁定目标审批人时，合同详情顶部固定展示“驳回”和本轮通过操作；总经理首次用印时通过操作显示“审批并签名”。顶部操作区位于页签容器之外，因此切换合同总览、合同关系、审批流程、合同附件或财务闭环等任一页签后仍可直接处理，不在审批流程页签重复展示第二组操作。合同附件在页签内按合同、发票、回单、用印申请单四组排列，只渲染非空组并在组标题显示数量；回款与付款回单归入同一组，未知及其他已归档类型回退合同组。页签总数继续使用原展示附件总数，分组不合并财务闭环或辅助档案数据。普通员工查看具体行政区合同详情时，可只读查看真实发票、回单、对应关系、已回款／未回款、完成率和核算基数；财务上传、确认、删除和冲正入口仍不显示。点击审批操作后在详情当前页面复用 `ContractApprovalWorkspace`（合同审批工作区）；非目标审批人不显示入口，工作区执行函数也会再次校验目标账号和审批中状态。审批人（包括总经理）从合同审批中心点击“查看详情”时，统一先进入“合同总览”页签，并保留待处理／已处理来源页签用于返回；不会自动跳到“审批流程”。详情左上角按来源显示“返回审批中心”。详情已发生节点展示真实操作时间、操作名称与“职位 姓名”，当前唯一的“等待职位 姓名审批”节点显示“待处理”。总经理点击“审批并签名”后进入专注签署状态，详情摘要、执行指标、生命周期和业务页签暂时隐藏；页面只保留当前单页用印申请单、可点击的总经理审批签署区和底部操作，不重复展示合同名称／金额摘要、工作区说明、审批意见、冗长签名提示或多层同义标题。总经理点击签署区后，系统在申请单右侧审批栏同一区域显示本人已锁定电子签名和“待提交”状态，并禁用签署区以避免重复请求。未完成签名确认、签名未锁定或签名／申请单加载失败时，“确认审批并签名”保持禁用；只有本人签名已确认且所有必需资料就绪后，才可提交审批与落签。成功后工作区继续保留，并切换为 `approvedFileId`（最终双签文件编号）对应的最终单页双签申请单，待本人核对后手动关闭；详情在工作区保留期间不提前刷新或隐藏双签结果。合同详情不再提供操作审计页签或前端审计请求，后台安全留痕仍保留。财务记录以草稿、已确认、已冲正三态展示，只有财务角色可对草稿确认／删除或对已确认记录冲正。

合同附件页签只在主合同详情显示，集中汇总同根主合同、补充协议和解除协议附件；补充及解除协议详情隐藏该页签。页面先按合同、发票、回单、用印申请单四类分组；合同、回单和用印申请单继续按来源合同分层，主合同在前、补充协议按序号升序、解除协议在后，每层标题显示来源标签、来源名称和数量，每个来源分别保留一个当前用印申请单。发票由主合同财务登记统一归档，在发票组直接集中展示，不再标注主合同／补充协议来源。页签总数使用聚合后实际展示文件数，文件卡片仍复用既有按角色预览／下载操作，且不读取财务闭环或辅助档案数据。

从合同详情的“合同关系”进入另一份主合同、补充协议或解除协议时，新详情记录上一个合同页面，左上角显示“返回上一个页面”。返回原审批合同后继续保留“返回审批中心”及原待办／已处理来源，不会错误跳至合同台账。

合同详情“财务闭环”的发票表格将销售方名称固定在单元格内，开票名称和超长发票号码完整换行展示。财务工作区统一改为纵向三阶段：发票、经营支出回单、最终对外付款。资产合同链条图顶部显示可供财务确认的资金承担方式：工程咨询直接付款、工程咨询划拨科技支付、科技自行承担或待核对。内部划拨模式下，工程咨询向科技的回单按付款日期计入工程咨询经营支出；科技向房东／供电方／物业方的最终付款只核销履约，不再重复增加支出。所有链条节点保持白色背景，只使用状态标签表达待划拨、待对外付款和已闭环。资产类二级分类名称包含“租赁”时，本页在资金链与财务登记之间直接显示内联押金管理，不打开弹窗；分类只触发高概率提示，押金金额仍须由合同原文确认。管理员可登记支付用途、工程划拨／科技自有／混合资金来源及其拆分，按退回、扣款、抵租金逐笔结算，并在具体退款行继续登记应退工程资金的实际退回金额、日期和说明；只读角色查看相同余额和结算留痕。

资产合同的对外付款回单行提供“登记押金”。点击后直接在当前回单下方展开押金条工作区，不打开弹窗；管理员可上传 JPEG（联合图像专家组）、JPG（图像格式）、PNG（便携式网络图形）或 PDF（便携式文档格式）原件并在页面内预览。页面显示 OCR（光学字符识别）金额；未识别出金额时由管理员对照原件手工填写并确认。确认前发现误传时显示红色“删除押金条”，点击后在当前工作区二次确认，删除成功后恢复上传入口。已经验证的押金不得直接删除，只能点击“撤销押金登记”，在行内填写必填撤销原因后撤销；页面保留原金额、撤销人、撤销时间和原因，并允许重新上传正确押金条。确认后回单行展示实际银行金额、已验证押金和需发票覆盖金额，并保留上传人、上传时间、验证人、验证时间和状态。未上传或未确认押金时不显示“已验证押金 0 元”。工程咨询划拨科技的内部资金回单不提供押金入口，只有直接付给合同对方的付款回单参与押金判断。

盖章核验弹窗同时展示审批快照、只读识别值、未舍入最终验证值和差异。甲方、乙方或金额的最终验证值不严格等于整数 100、字段缺失、内容错误或发生候选冲突时整次核验不通过，只提供重新识别或重新上传，不提供逐字段人工确认和补录；盖章版合同日期无法识别时按原始业务规则自动采用上传日期并标明来源，但该兜底值不是 OCR 100，不得在页面或审计中冒充。此回退规则不适用于草拟合同。可靠识别结果与审批快照存在差异时，要求财务填写说明，并按“已关联项目的主营合同由项目负责人、未关联项目及其他合同由唯一活动总经理”的规则重新锁定本轮复审人；复审通过后才出现最终归档入口。

## 注意事项

1. **路由命名**：
   - 所有路由必须设置唯一的 `name`
   - 便于编程式导航和路由跳转

2. **权限控制**：
   - `meta.permission` 与后端权限保持一致
   - 前端权限检查仅用于 UI 展示
   - 后端必须有对应的权限验证
   - `/users` 使用管理员路由守卫；后端 `/api/users` 仍独立校验数据库中的实时角色

3. **懒加载**：
   - 大型页面组件必须使用懒加载
   - 避免首屏加载过大的 bundle

4. **路由嵌套**：
   - 保持路由层级简洁
   - 避免过深的嵌套层级

### 公证费付款通知入口

新增合同的资产二级分类提供“公证费”，选中后固定独立主合同关系并说明“已盖章付款通知识别通过后直接生效，无需审批或再次用印”。成功后直接跳转详情，不再停留在普通合同审批步骤。详情以付款单位、对方名称、通知标题和通知日期展示对应字段。列表筛选及元数据回退包含公证费分类。

### 资产财务登记顺序

资产类直接付款支持先付款后开票、先开票后付款，以及分次付款和分次补票。无发票时按主合同中唯一我方单位与对方名称校验回单双方，资金方式必须已明确为直接支付；付款保存后按真实银行日期确认付款事实，财务登记保持待补发票。补票时重新核对发票购销双方与全部累计回单，只为金额重叠部分建立配对，金额与配对全部闭合才确认整笔登记，不重复确认已经入账的付款。已付款完成的合同仍可为未闭合登记补发票，但不能借此新增付款。内部划拨模式继续沿用既有对外付款与工程划拨两条资金链。

## 开票申请页面路由

- `/contract-applications/mine`：普通员工统一“我的申请”页面，以按需挂载页签切换“合同下载申请”和“开票及用印申请”；未打开的下载页签不会误确认结果已读。开票页签内再区分“当前申请／历史申请”：草稿、审批中、驳回待修改、待盖章和待开票属于当前申请，流程已完成的记录进入历史申请；两类列表均显示跨分页连续序号。
- `/invoice-applications/new`：员工发起或通过查询参数继续编辑本人草稿。本次开票／付款金额由申请人根据本次实际业务填写，系统只校验金额大于零且不超过剩余可申请额度；主营合同同时将已开票金额与尚未被正式发票覆盖的有效申请余额作为之前累计，自动计算本次累计并在线生成三页三联单。编辑已有草稿或驳回申请时保留原申请金额。
- `/contract-download-requests/mine`、`/invoice-applications/mine`：保留为兼容地址，分别重定向至统一页面的下载、开票页签并保留原查询参数。
- `/invoice-applications/approval`：采用与合同审批一致的渐变工作台页头、当前视图数量、刷新、服务端搜索和“待我审批／审批记录”页签。待办只显示提交时锁定给当前总经理且尚未处理的开票申请；审批记录显示当前总经理本人已经通过或驳回的申请，并保留后续流程状态。两个页签的内容均显示跨分页连续序号。侧边栏二级菜单显示数字角标，一级“合同管理”分组只显示红点。
- `/invoice-applications/tasks`：管理员处理待盖章交付、已开具登记和待财务登记任务。主营三联单的主操作只调用“打印”接口，不使用完整原件代替“其他费用”工作表打印件；只有完成“登记已开具”后才显示前往合同财务登记上传正式发票的入口。

三类工作台共用同一状态展示组件，但操作按钮严格按登录人角色和当前状态显示。管理员只执行盖章交付和开具登记，不显示审批按钮。
