# 账号密码认证模块

## 模块概述

账号密码认证模块提供了系统的用户认证和授权功能，取代了原有的飞书OAuth认证方式。本模块支持：

- 账号密码登录
- 密码修改
- 本人电子签名首次确认与锁定
- 管理员创建/管理用户账号
- 基础审批功能

## 数据模型

### 用户表 (users)

```sql
CREATE TABLE users (
  id TEXT PRIMARY KEY,
  username TEXT UNIQUE,           -- 登录用户名
  password_hash TEXT,             -- 密码哈希（bcrypt）
  name TEXT NOT NULL,             -- 显示名称
  email TEXT,
  mobile TEXT,
  avatar_url TEXT,
  role TEXT NOT NULL DEFAULT 'user',  -- super_admin, chairman, admin, general_manager, boss, user, guest
  status TEXT NOT NULL DEFAULT 'active',  -- active, inactive
  department TEXT,
  position TEXT,
  force_change_password BOOLEAN NOT NULL DEFAULT false,  -- 是否需要强制修改密码
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL,
  last_login_at TEXT
);
```

### 审批流程表 (approval_flows)

```sql
CREATE TABLE approval_flows (
  id TEXT PRIMARY KEY,
  name TEXT NOT NULL,             -- 流程名称
  type TEXT NOT NULL,             -- 审批类型
  steps_json TEXT NOT NULL,       -- 审批步骤配置（JSON）
  is_active INTEGER NOT NULL DEFAULT 1,
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL
);
```

### 审批实例表 (approval_instances)

```sql
CREATE TABLE approval_instances (
  id TEXT PRIMARY KEY,
  flow_id TEXT,
  type TEXT NOT NULL,
  target_id TEXT NOT NULL,
  target_type TEXT NOT NULL,
  applicant_id TEXT NOT NULL,
  current_step INTEGER NOT NULL DEFAULT 1,
  status TEXT NOT NULL DEFAULT 'pending',  -- pending, approved, rejected, cancelled
  submit_time TEXT NOT NULL,
  complete_time TEXT,
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL
);
```

### 审批记录表 (approval_records)

```sql
CREATE TABLE approval_records (
  id TEXT PRIMARY KEY,
  instance_id TEXT NOT NULL,
  step INTEGER NOT NULL,
  approver_id TEXT NOT NULL,
  action TEXT NOT NULL,           -- approve, reject, comment
  comment TEXT,
  action_time TEXT NOT NULL
);
```

## 使用说明

### 1. 创建初始管理员

首次部署系统时，需要通过命令行创建管理员账号：

```bash
npm run create:admin
```

按照提示输入：

- 用户名（仅字母、数字、下划线，至少3个字符）
- 密码（至少6个字符）
- 显示名称

### 2. 登录系统

访问登录页面，输入用户名和密码即可登录。

### 3. 管理用户

管理员和超级管理员可以在"用户管理"页面：

- 创建新用户
- 编辑用户信息（角色、状态、部门等）
- 重置用户密码
- 删除用户

### 4. 修改密码

用户可以在"个人设置"页面修改自己的密码。

### 5. 电子签名

- 每个可参与签署的账号只能在个人设置中确认一份本人签名，不再提供代管他人签名
- 签名读取和首次保存均以当前会话账号为边界，不允许提交其他用户编号
- 确认成功后前端按钮锁定；后端使用事务锁阻止并发重复上传，并拒绝后续覆盖和删除
- 上传时自动识别完整签名笔迹、去除纸张背景并裁剪留白；竖拍或竖向排列的签名会自动转为横向，确认前可使用左右旋转按钮校正方向
- 转正流程中必须由员工、总经理、管理员和董事长分别调用自己的签名

### 6. 审批功能

- 员工提交审批请求（工作日志、报销单等）
- 管理员在"审批中心"处理审批
- 支持通过/驳回/撤销操作

## 安全措施

### 密码安全

- 使用 bcrypt 算法进行密码哈希（salt rounds = 10）
- 密码最小长度 6 个字符
- 密码最大长度 128 个字符
- 不存储明文密码

### 会话管理

- 使用 PostgreSQL 存储会话
- 会话有效期 7 天
- HttpOnly Cookie
- SameSite = 'lax'
- 每次受保护请求都会重新读取数据库中的账号状态和角色；账号停用、删除后旧会话立即失效，角色调整后旧会话立即使用新权限
- 生产环境必须显式配置 `SESSION_SECRET`（会话签名密钥），缺失时服务拒绝启动；开发环境仅使用固定的开发专用默认值

### 权限控制

- 系统角色包括超级管理员、董事长、管理员、总经理、BOSS、普通用户、访客
- 用户管理页面及完整用户接口允许管理员、超级管理员和董事长使用
- 普通管理员可以创建、编辑、删除用户和重置密码，但不能修改、删除或重置超级管理员账号
- 业务页面读取同事列表时使用精简目录，不暴露手机号、邮箱、收款信息和密码字段
- 后端角色中间件每次从数据库读取当前角色，不能只依赖前端菜单或会话中的旧角色
- BOSS是无需员工档案的轻量账号，登录后直接进入只读经营看板，不执行入职资料检查
- BOSS仅可修改密码、退出登录和保存个人偏好；员工档案、电子签名及其他业务写请求由后端统一拦截
- BOSS角色不进入总经理审批角色集合，不获得报销、请假、转正和离职审批能力
- `requireGeneralManager` 继续用于仅总经理可处理的业务；请假待办、审批记录、通过和驳回改用 `requireLeaveApprover`，只允许数据库当前角色为总经理或董事长的账号通过，管理员与超级管理员调用时返回权限不足
- 超级管理员是系统最高角色，包含管理员能力，并保留各业务流程的终审或越权处理能力
- 董事长是无需员工档案的轻量账号，创建时只填写用户名、密码和角色，登录后不执行员工入职资料检查
- 董事长复用超级管理员权限矩阵；转正流程最终审批只允许董事长本人处理，申请单仍沿用原模板最后审批栏
- 五类离职档案齐全时账号保持原状态；管理员逐项预览并确认离职后，原账号才改为停用且现有会话立即失效。管理员可在用户管理中重新激活该账号
- 账号重新激活不等于返聘：原员工档案仍保持已离职，返聘必须新建账号和新员工档案
