# 05 - 用户管理模块

## 模块概述

用户管理模块用于管理系统用户信息、角色分配和权限设置，支持用户查询、编辑和权限管理。

## 主要功能

### 1. 用户列表管理
- 查看所有系统用户
- 用户信息展示（姓名、邮箱、角色、状态）
- 用户搜索和筛选
- 用户状态管理（启用/禁用）

### 2. 角色管理
- 分配用户角色
- 角色权限查看
- 批量角色分配

### 3. 用户信息编辑
- 更新用户基本信息
- 员工角色创建时自动生成员工编号，编辑时可由管理员修改员工编号
- BOSS为独立轻量账号，仅维护用户名、密码、角色和账号状态
- 修改用户角色
- 重置用户密码（如适用）

### 4. 用户活动监控
- 查看用户登录历史
- 用户操作日志
- 活跃度统计

## 数据模型

### User（用户）
```typescript
{
  id: string
  username: string | null           // 登录用户名
  password_hash: string | null      // 密码哈希
  name: string                      // 显示名称
  email?: string | null             // 邮箱；BOSS账号为空
  mobile?: string | null            // 手机号；BOSS账号为空
  avatar_url?: string               // 头像 URL
  role: 'super_admin' | 'admin' | 'general_manager' | 'boss' | 'user' | 'guest'  // 用户角色
  status: 'active' | 'inactive'     // 用户状态
  department?: string               // 部门
  position?: string                 // 职位
  employee_no: string | null        // 员工编号；BOSS账号为空
  last_login_at?: string            // 最后登录时间
  created_at: string
  updated_at: string
}
```

## API 接口

| 接口 | 方法 | 说明 |
|------|------|------|
| `/api/users` | GET | 管理员获取包含账号、角色、联系方式和收款信息的完整用户列表 |
| `/api/users/directory` | GET | 已登录用户获取精简同事目录，不返回BOSS及联系方式、收款信息和密码字段 |
| `/api/users/next-employee-number` | GET | 管理员获取创建弹窗中展示的下一个员工编号 |
| `/api/users` | POST | 管理员更新用户信息 |
| `/api/users/activities` | GET | 查看本人活动；管理员可指定用户查看 |
| `/api/users/create` | POST | 管理员创建新用户 |
| `/api/users/:id` | DELETE | 管理员删除用户 |
| `/api/users/:id/reset-password` | POST | 管理员重置用户密码 |

## 使用示例

### 获取用户列表
```typescript
import { api } from '@/utils/api'

const fetchUsers = async (filters?: any) => {
  const params = new URLSearchParams()

  if (filters?.role) params.append('role', filters.role)
  if (filters?.is_active !== undefined) {
    params.append('is_active', String(filters.is_active))
  }
  if (filters?.search) params.append('search', filters.search)

  const response = await api.get(`/api/users?${params}`)
  return response.data
}
```

普通业务页面如只需要负责人、同事名称等公开字段，应调用精简目录：

```typescript
const response = await api.get('/api/users/directory')
```

### 更新用户角色
```typescript
const updateUserRole = async (user: User, role: string) => {
  await api.post('/api/users', { ...user, role })
}
```

### 禁用用户
```typescript
const disableUser = async (user: User) => {
  await api.post('/api/users', { ...user, status: 'inactive' })
}
```

## 角色权限对照表

| 角色 | 权限描述 |
|------|----------|
| `super_admin（超级管理员）` | 所有管理权限，可修改超级管理员账号和授予超级管理员角色 |
| `admin（管理员）` | 用户管理及主要业务管理权限，但不能修改或删除超级管理员账号 |
| `general_manager（总经理）` | 总经理专属审批权限，不具备用户管理权限 |
| `boss（BOSS）` | 独立轻量查看账号，只读查看公司经营看板，不建立员工档案，不继承审批权限 |
| `user（普通用户）` | 查看和编辑自己的数据，使用公共业务数据 |
| `guest（访客）` | 受限查看权限 |

详细权限矩阵参见 [src/types/index.ts](../src/types/index.ts) 中的 `ROLE_PERMISSIONS`。

## 初始管理员创建

### 命令行工具
```bash
npm run create:admin
```

按提示输入：
- 用户名（仅字母、数字、下划线，至少3个字符）
- 密码（至少6个字符）
- 显示名称

### 注意事项
- 首次部署必须通过命令行创建初始管理员
- 后续用户由管理员通过用户管理页面创建
- 角色存储在数据库中，可通过管理界面修改

## 创建用户规则

### 必填字段
| 字段 | 要求 | 说明 |
|------|------|------|
| 用户名 | 必填，至少2个字符 | 使用员工姓名，用户名即为显示名称 |
| 密码 | 必填，至少6个字符 | 登录密码 |
| 邮箱 | 员工角色必填，需有效格式 | 用于员工联系信息；BOSS不填写 |
| 手机号 | 员工角色必填，必须11位 | BOSS不填写 |
| 部门 | 员工角色必填 | BOSS不填写 |
| 职位 | 员工角色必填 | BOSS不填写 |

### BOSS轻量账号

- 创建时只填写用户名、密码和角色。
- 不生成员工编号，不填写邮箱、手机号、部门、职位、员工状态和收款信息。
- 不创建 `employee_profiles`（员工档案）记录，也不进入入职、工资、假期和员工候选流程。
- BOSS账号必须独立创建，不能由员工账号改为BOSS，也不能改回员工角色。
- 编辑BOSS时只能修改用户名、密码和账号状态，角色固定为BOSS。

### 自动字段
| 字段 | 规则 | 说明 |
|------|------|------|
| 员工编号 | 创建时自动取系统已有最大 `YULI-CS` 数字序号后加 1 | 保持 `YULI-CS` 加 3 至 6 位数字格式，若历史最大编号使用更长数字宽度则沿用该宽度，少于 3 位自动补零 |

### 选填字段
| 字段 | 要求 | 说明 |
|------|------|------|
| 角色 | 选填，默认为普通用户 | admin/general_manager/boss/user/guest |

### 验证规则
- **用户名**：不能重复，至少2个字符
- **密码**：至少6个字符
- **手机号**：必须是11位数字，以1开头，第二位为3-9
- **邮箱**：如填写需符合邮箱格式
- **手机号唯一性**：在职、实习期员工的手机号不能重复；员工已离职后，返聘新账号可复用原手机号，但用户名和员工编号仍必须唯一
- **创建一致性**：员工账号和员工草稿档案在同一事务中创建；BOSS只创建账号，不创建员工草稿档案
- **入职日期来源**：创建和编辑账号均不能填写入职日期；系统取该员工第一份已识别劳动合同的开始日期，并同步展示到员工基础信息和员工数据；没有成功识别合同起止日期时保持为空
- **正常转正流程**：待提交或已驳回的员工由本人在转正页面上传、修改并提交申请表，员工数据中的管理员档案入口不代替员工操作
- **转正材料补录**：直接创建为“在职”且无转正记录的员工可补录转正申请表；已有“已转正”记录但缺少申请表时也可补传一次，且不改变原审批状态
- **正式档案展示**：正常流程中的申请表只有转正通过后才进入员工数据的转正档案；待提交、审批中和已驳回材料不在正式档案中展示
- **员工编号**：创建时后端在事务锁内扫描 `users` 和 `employee_profiles` 已有有效编号并生成下一号；编辑时仍可由管理员修改，后端统一转为大写、校验格式和唯一性，并在同一事务内同步员工基础档案记录；数据库启动时不再为空编号自动补号
- **资料联动**：修改员工编号后，员工下次预览或下载入职邀请函、新员工入职申请表、劳动合同书模板时自动使用最新编号；管理员补录的人事档案内容、原编号和文件名均保持上传原样
- **合同模板日期**：管理员在员工数据中维护合同模板期限和可选试用期，员工下载劳动合同书模板时自动写入；模板拟定日期不直接更新正式入职日期、合同到期日期或转正记录
- **部门职位联动**：创建和编辑用户时实时读取“部门职位管理”的最新配置；职位必须属于当前部门，新增职位保存后无需刷新页面即可在编辑下拉框中选择
- **账号档案同步**：用户管理或员工数据任一入口修改部门、职位后，`users` 与 `employee_profiles` 在同一事务内同步，劳动合同模板始终使用员工当前职位
- **离职账号联动**：五类离职档案齐全后先保持员工和账号原状态，由管理员逐项预览核对并点击确认；确认后原员工档案改为已离职、原账号立即停用。管理员可单独重新激活原账号，但不能把原员工档案恢复为在职
- **返聘规则**：员工重新入职时必须创建新账号和新员工档案，使用新的用户名和员工编号，不能复用原已离职档案继续工作

## 注意事项

1. **角色变更**：
   - 角色变更立即在数据库生效
   - 后端接口权限立即生效，前端菜单可能需要刷新或重新登录
   - 降低用户权限需谨慎操作
   - BOSS是独立轻量账号，禁止与员工角色互相转换

2. **用户禁用**：
   - 禁用用户会立即阻止其登录
   - 后端每次请求重新校验账号状态，已登录会话也会立即失效
   - 重要用户禁用前需要确认

3. **数据安全**：
   - 密码使用 bcrypt 加密存储
   - 操作日志完整记录
   - 定期备份用户数据

4. **权限要求**：
   - 用户管理页面和完整用户接口仅管理员、超级管理员可访问
   - 管理员可创建、编辑、删除用户和重置密码，但不能操作超级管理员账号
   - 当前登录账号不能停用或删除自身
   - 普通业务页面必须使用精简同事目录，不能复用完整用户接口
